# 家庭健康看板桌面应用
## 产品需求与实施方案 · v1.0

**方案日期：2026-09-17**  
**目标交付：macOS / Windows 同一代码库的公开测试版（Beta）**  
**AI 主路径：本机 Codex App Server + Codex 管理的 ChatGPT 账户登录**  
**实现对象：后续接手项目的 Codex 开发 Agent**  
**状态：产品范围已确认；外部接口、打包及安全能力必须先通过集成验证，不代表应用已实现。**

> 产品是一款由 AI 持续维护的家庭健康看板，不是通用聊天客户端，不是需要用户自行编排的技能包，也不是医疗诊断或处方系统。用户通过添加成员、导入资料、查看变化和处理少量例外完成操作；正常路径不需要输入提示词、描述技能、写 JSON 或运行终端命令。

# 0. 已冻结的产品决策

| ID | 决策 | 约束与解释 |
|---|---|---|
| D01 | 同时交付 Mac 和 Windows，维护同一套代码 | 同一仓库、同一产品版本、共用业务逻辑与 UI；不同系统和 CPU 架构仍需不同安装包及测试。不是“一个二进制运行所有系统”。 |
| D02 | 第一版由单个家庭管理员在本机管理全部成员 | 不开公网服务，不做局域网手机访问、多账号或成员级远程权限；未来可扩展远程只读访问。 |
| D03 | App 是前台，Codex 是执行引擎 | 使用 App Server 的受支持协议；用户不必安装或操作官方 Codex 桌面界面，App 管理自己的 Codex 运行时。 |
| D04 | 使用 Codex 管理的 ChatGPT 登录 | 不自己托管 OAuth，不收集账户密码，不要求复制认证文件，不把登录令牌用于非公开接口。 |
| D05 | 无需填写提示词或技能描述 | 固定任务模板、上下文构造和阶段调度由产品封装；手动补充病史等是健康资料，不是提示词。 |
| D06 | 尽量全自动 | 通过自动接纳规则的新增资料与解释自动进入看板；只有身份、关键事实、版本覆盖或安全例外需要用户处理。没有逐阶段批准按钮，也没有默认的最终总确认。 |
| D07 | 格式支持 PDF、JPG/JPEG、PNG、HEIC/HEIF、Word、TXT、手动输入 | Word 包含 `.docx` 和旧 `.doc`，实现路线及兼容组件门禁见第 7 章；宏文档不在支持范围。 |
| D08 | 图片由 Codex 理解 | App 负责解码、方向修正、PDF 页面渲染等机械预处理；不以第三方云 OCR 替代 Codex，默认不新增外部模型服务。 |
| D09 | 报告收件箱自动发现，每天处理一次，支持手动触发 | 发现后 UI 立即显示待处理数量；默认不立刻启动 AI；到每日时点处理，用户也可以点击“立即处理”。 |
| D10 | 打开 App 不再次解锁 | 第一版不做 PIN、应用密码、Touch ID 或 Windows Hello 页面；不等于允许公开文件或忽略本机安全。 |
| D11 | 全新数据开始，不迁移旧项目真实资料 | 不提供旧 JSON/旧 manifests 迁移工具，不扫描用户旧家庭资料目录；仅参考旧项目架构与虚构样例。 |
| D12 | 重新设计桌面 UI，保留温暖、克制、低焦虑的理念 | 不把 430px 手机页面放大套壳；采用桌面导航、信息分栏和证据侧栏。 |
| D13 | 先集成原型，再公开 Beta | Mac 与 Windows 都是 Beta 必须通过的平台，不能做完 Mac 后把 Windows 无限期延期。 |
| D14 | 首版手动补充与纠错、基础后续事项管理、处理通知 | 基于档案的自由问答、到期复查推送、远程访问、应用解锁、其他 LLM API 路径留到后续。 |

# 1. 产品定义与成功标准

## 1.1 一句话定义

一个在本地保存家庭健康档案、利用用户自己的 Codex 权益持续整理新报告的桌面看板。它把多年的报告变成可核对的事实、可理解的变化和有出处的后续事项。

## 1.2 核心使用场景

**首次建立档案：**用户安装 App，登录、创建成员、指定报告收件箱，放入历史报告。App 自动分批提取、核对并建立看板。用户只处理无法可靠确定的例外。

**后续更新：**用户把新报告放到成员对应文件夹。App 显示“发现新资料”；每天到点批处理，或点击立即处理。既有历史不被静默覆盖，看板说明本次新增与修正。

**平时查看：**用户查看家人的资料覆盖、器官系统、指标变化、就医事件、原报告证据、后续事项和生活指南。即使退出 Codex 或额度不足，已有档案仍然可读。

**补充信息：**用户直接填写既往史、用药、过敏、自测指标或一段补充说明，明确记录这是本人补充的资料。AI 可以整理它，但不能把自述伪装成正式检查结果或医生诊断。

## 1.3 目标用户与边界

首批用户是会使用 AI Agent、愿意使用个人账户处理自己和已获授权家人资料的成年人。最终界面无需暴露 Agent 术语。一个 OS 用户对应一个本地管理员；同一工作区中的成员不是独立登录用户。

不把产品定位为临床病历系统、医院审核系统、实时急救监测、自动诊疗决策、处方生成或专业医疗器械。报告已经写明的诊断可以保存；AI 自己推断的疾病不能升级为“医生确诊”。[S20]

## 1.4 可验收的成功定义

| 目标 | 验收口径 |
|---|---|
| 无提示词操作 | 从新安装到首份报告进入看板，全程不要求终端、提示词、JSON 或手动安装技能。 |
| 正常资料自动完成 | 在定义的清晰、已归属、无冲突测试集上，从导入到看板更新无需逐阶段确认。 |
| 可追溯 | 所有显示为报告事实的关键字段能回到文件、页/图/文档块/行号和原始文本；无法定位不得伪造定位。 |
| 不丢历史 | 同日多次就诊不覆盖、同文件重复导入不重复计数、旧值修正有版本链。 |
| 可恢复 | 中断、重启、额度不足、硬盘不足后能看到准确状态，并从安全检查点继续。 |
| AI 可替换边界 | 领域层不依赖 Codex 的 thread ID 作为成员或报告 ID；首版只实现 Codex 适配。 |
| 双平台一致 | 两个平台通过同一套业务验收，并额外通过各自的安装、认证、图片、文件监控与后台行为测试。 |

**这些是目标，不是已取得结果。**不以 Star 数、LLM 调用次数或模型自己给的置信度作为首版质量证明。

## 2.2 明确不做

首版不做公网部署、家庭多账号、云同步、手机 App、共享 OAuth、额外 LLM API Key 模式、开放模型商店、自由聊天问答、自动预约、医生联系、处方调整、运动/营养治疗处方、持续生理监控、旧项目数据迁移、无进程状态下的系统守护执行、应用打开时解锁。

## 2.3 报告内容范围

首版重点支持常见体检报告、检验单、超声/CT/MRI 等**文字报告**。用户可以用 Word/TXT 和手动输入补充病史、用药、过敏和其他说明。

不把医学影像像素解释当作首版能力：DICOM、原始 CT 序列、病理切片和皮损照片诊断均不在范围。图像文件中的**报告文字、表格和已有结论**属于支持范围。

遇到手写、复杂病历、出院记录中的不确定内容，应保留来源并标记可读范围；不能宣传所有医疗文档都可准确解析。清晰的自述与文字结论可归档，专用的处方识别和出院病程结构化不列为首版独立模块。

# 3. 技术主方案与复用边界

## 3.1 主技术栈

| 层 | 选择 | 原因与约束 |
|---|---|---|
| 桌面外壳 | Electron | 一套 Web UI 与 TypeScript 业务代码；本机文件、托盘、子进程与系统事件由主进程管理。 |
| 界面 | React + TypeScript + Vite + Tailwind | 延续现有项目主要能力；重新设计桌面布局，不维持两套 Mac/Windows 页面。 |
| 领域与契约 | TypeScript + Zod，按选定版本导出 JSON Schema | 内部校验、IPC、AI 结果和测试使用同一语义契约；不能手写多套互相漂移的类型。 |
| 本地正式存储 | SQLite + better-sqlite3 | 单机事务与查询；由一个应用数据服务写入，重操作进入独立 worker；不把所有状态散成可任意覆盖的 JSON。 |
| 原始资料 | 文件型不可变对象存储 + DB 元数据 | 保存字节哈希、来源与衍生文件；不把 PDF 和图片直接塞进 JS bundle。 |
| Codex 适配 | 版本锁定的 App Server，stdio 双向通信 | 不读终端输出猜状态；不模拟官方 App 的 UI；不建立远程 App Server。 |
| 文件监控 | Chokidar + 全量对账扫描 | 文件事件用于及时发现，对账扫描保证恢复后不漏文件。[S12] |
| PDF | PDF.js | 页面渲染与文本层读取；扫描页交给 Codex 视觉。[S13] |
| DOCX | 本地 OOXML/文档解析适配器，优先评估 Mammoth | 提取段落、表格和内嵌图片；必须禁外部引用并净化输出，Mammoth 自身不是安全 HTML 净化器。[S14] |
| 旧 DOC | 隔离的 Word 兼容转换组件 | 首选封装经过验证的 LibreOffice headless 转换，不要求用户安装 Word；详见 7.3。[S15] |
| 图片 | 统一解码、方向与尺寸适配器 | JPG/PNG 使用本地解码；HEIC/HEIF 用选定跨平台 WASM/运行时解码组件，必须验证许可证与三个目标架构。 |
| 测试 | Vitest + 应用集成测试 + Playwright/Electron 场景 | 模拟协议和真实账户 smoke 分开，真实账户不放公开 CI。 |
| 打包 | electron-builder + GitHub Actions matrix | 原生依赖按 Electron ABI 重建；在目标平台构建/测试。[S09][S10] |

依赖版本在 G0 中选择并锁定，形成 `runtime-lock.json`、锁文件和兼容矩阵。不得把本文未验证的版本号当作最新版。不得在用户机器首次启动时执行不固定版本的 `npm install`、`pip install` 或自动下载任意最新模型工具。

## 3.2 参考现有仓库，不迁移其真实数据

参考仓库：`badDevBuild/family-health-dashboard-template`；本轮读取的固定基线为 `e74d59c797a9a4898ad8a0679de1f88cc8b2ac1e`，2026-09-17 的“丰富演示病例与诊断证据”提交。[S01]

值得沿用：健康事件与指标的事实基础、器官系统与时间线两种阅读方式、证据引用、虚构演示、数据不足不是正常、事实与分析分层、流水线阶段、隐私与回归测试理念。[S02]

需要改变：私有数据编译进前端的路径、以手写 manifests 表示人工批准、手机单列布局、由人工运行多个脚本的更新方式。新产品采用运行时数据服务、App 自动决策记录和桌面交互。

实施前先检查工作区和用户当前分支。推荐在现有仓库的新功能分支增加 `apps/desktop/` 与共享包，保留当前演示站，直到新演示能够替代。不得删除原项目、强推 main，或替用户发布 Release。现有已验证纯虚构样例可转换为新测试夹具；这不是旧真实数据迁移功能。

# 4. 架构、进程与权限

## 4.1 数据流

```text
用户资料 / 受授权收件箱
        ↓
本地登记、稳定性检查、字节哈希、不可变拷贝
        ↓
页面 / 文档块 / 图片证据包
        ↓
持久任务编排器 ── CodexAdapter ── 本机 App Server ── OpenAI 模型服务
        ↓                                ↑
候选输出、自动规则与 AI 复核               仅本任务最小化证据与上下文
        ↓
事实版本提交 / 派生快照提交（SQLite 事务）
        ↓
桌面看板通过受控 IPC 实时读取、展示证据与变化
```

图中的云端通信由 Codex 管理，不经过开发者自建服务器。没有“报告先上传到本项目服务器”的环节。授权模型处理不是同意把资料加入 GitHub、遥测或公开错误报告。

## 4.2 进程分工

**Renderer：**只显示 DTO 和受控的资料流；无 Node、无任意文件系统访问、无 Codex 原始协议、无 OAuth token。预览不渲染任意脚本、远程图片或报告内活动内容。

**Preload：**通过 `contextBridge` 暴露按业务命名的方法；不暴露 `ipcRenderer`、`exec`、任意 URL 请求或任意路径读取。

**Main：**负责窗口、系统文件选择、权限入口、托盘、计划时点、账户状态和子进程生命周期；所有入站 IPC 二次校验和 sender 校验。

**App 数据/任务服务：**可先在独立 worker 实现，独占正式写入；保持持久任务、事务、版本检查、受控数据查询。大文件 hashing、转换、备份不阻塞窗口。

**转换进程：**只接受本次复制到隔离目录的文件，不读取系统文档目录；不启用宏、外部链接和联网资源。子进程不自动成为安全沙箱，必须有真实权限与资源边界。

**Codex 进程：**使用 App 私有 `CODEX_HOME`，不继承用户开发环境的插件、AGENTS.md、MCP 和凭据文件；只收到任务构造的输入。

Electron 的上下文隔离、渲染沙箱、CSP、IPC sender 校验和导航限制均是基础安全要求，而不是 UI 完成后的补丁。[S08]

## 4.3 推理优先，默认不让模型运行任意命令

本产品的核心任务是“读取已准备证据，返回结构化候选结果”。首版不需要 Codex 自己安装工具、写解析脚本或修改程序。

默认配置目标：关闭 shell / unified exec / web search / 外部 apps / 未审核插件与 MCP / 自动依赖安装；使用最小只读权限与禁止升级权限策略。配置 key 必须以所锁运行时为准；官方配置说明中存在 shell、执行与搜索等开关，但它们的组合必须真实验证。[S07]

**禁止把 `approvalPolicy=never` 理解为禁止所有工具。**它是批准交互策略；允许的工具仍可能执行。权限白名单与工具可用性必须分别验证。

G0 的安全验收必须包含：恶意报告要求读取其他目录、运行程序、读取凭据、修改正式库和访问外站；观察到的实际工具集和访问结果必须符合预期。若无法可靠禁用任意执行，应保持技术预览、不启用无人值守真实资料处理，或者完成有证据的 OS 级沙箱方案后再放行；不得通过“提示模型不要做”宣布隔离完成。

不要调用 App Server 中用于用户主动 shell 操作、且不继承线程沙箱的接口。产品没有“运行任意命令”功能，也不需要开放该能力。[S03]

## 4.4 本机网络边界

业务层不用公开监听端口。Renderer 与 Main 用 IPC，Main 与 Codex 用 stdio。OAuth 浏览器回调由 Codex 自己管理；这是认证所需的临时本机回调，不是产品公网服务。

明确区分“沙箱命令不能访问外网”和“Codex 模型推理必须访问 OpenAI”：不能因为禁用工具网络，就宣称推理本地化。

# 5. 信息架构与桌面 UI

## 5.1 桌面布局

推荐最小窗口 1100 × 720，常规设计宽度 1440。窄窗口保持主要操作可达，不使用仅靠 hover 的入口。左侧导航约 208–232px；主内容为 2–3 列信息区；需要核对时打开右侧证据栏，较小窗口可切换为全宽双栏核对页。

导航：**家庭总览、成员档案、报告收件箱、处理中心、后续事项、设置**。成员详情内部保留“概览 / 身体 / 指标 / 时间线 / 生活指南 / 资料”。

顶部长期显示轻量 AI 状态：已连接、待登录、额度不足、处理中、已暂停；AI 状态不能覆盖健康状态。没有资料不显示空白健康分数；没有分析不显示绿色正常。

## 5.2 页面规范

| 页面 | 核心内容 | 主要操作与状态 |
|---|---|---|
| 首次启动 | 产品定位、本地与云端边界、虚构体验、开始使用 | 可跳过登录先看演示；没有真实资料也能启动。 |
| 初始化向导 | 工作区、Codex 登录、成员、收件箱、每日时间与授权摘要 | 分步保存；退出后恢复到已完成步骤；无需重复登录。 |
| 家庭总览 | 各成员最近资料日期、待处理数量、本次变化、后续事项 | 点击成员进入；日期过旧提示资料截至时间，不作风险诊断。 |
| 成员概览 | 资料覆盖、已记录病史、最近变化、待核对和后续事项 | 添加报告、手动补充、查看证据；修改背景不立即全家重算。 |
| 报告收件箱 | 文件、来源目录、发现时间、成员、状态、下一次处理时间 | 筛选、批量归属、立即处理、忽略、重试；发现但未发送时明确标示“尚未发送至 AI”。 |
| 处理中心 | 按批次/成员/阶段的进度，等待原因、重试次数 | 暂停队列、取消、继续、查看已完成部分；没有伪造倒计时。 |
| 例外核对 | 原文和候选值并排；冲突、证据页、影响范围 | 修正、选定成员、保留未知、暂缓；不能“忽略错误并标记全部可信”。 |
| 指标页 | 最新事实、报告参考范围、历史序列、单位与方法 | 比较同指标可比序列；缺失断开、定性分开、可切回表格。 |
| 时间线 | 按临床日期排序的检查/就诊/自述事件 | 同日多个事件独立展示；未知日期单独分组，不拿导入时间冒充。 |
| 原始报告 | 安全预览、页或文档块导航、引用字段 | 证据高亮可降级为页定位；不生成模型猜测的矩形框。 |
| 后续事项 | 医生原文事项、AI 待核实事项、用户安排 | 标记已咨询/已安排/已完成、关联新记录；没有自动预约。 |
| 生活指南 | 与资料对应的一般生活教育、来源、更新时间 | 不输出处方或个性化治疗剂量；不足时明确标记通用内容。 |
| 设置 | 账户、运行时、收件箱、每日时点、存储、通知、备份、诊断 | 不含“重新设置 PIN”；退出模型不删除健康数据。 |

## 5.3 视觉原则

延续温暖背景、低饱和主色、充足留白和清晰文本层级。资料/处理状态使用文字标签而不只靠颜色。颜色不能把“数值下降”天然解释为改善。

没有病历证据时不使用“确诊”“病情改善”“治愈”等表述。用“报告记录”“资料显示”“AI 整理，尚需专业核实”“资料不足”描述来源与程度。

尽量避免“健康 72 分”这类无法解释的综合分数、焦虑式红色大屏、无依据的好坏排名和过度拟人化医生肖像。默认不显示链式思考或原始模型推理，仅显示任务阶段、证据和必要的决策摘要。

## 5.4 核心文案样例

- 发现：“发现 3 份新资料，计划今天 20:00 处理。现在也可手动开始。”
- 授权：“本目录新增资料将按计划发送给 OpenAI，通过你的 Codex 账户整理。资料仍保存在本机。”
- 完成：“新增 2 次检查，更新 6 项指标；1 份资料需要确认所属成员。”
- 额度：“Codex 当前额度不足，已暂停。已有档案仍可查看。”
- 休眠：“错过的批次会在应用下次运行时合并补处理。”
- 无资料：“还没有可分析的资料。添加报告或补充记录后，这里会逐步建立档案。”
- 自动接纳：“AI 已整理并通过数据检查。”不要写“医生已审核”。
- 旧分析：“已新增报告；此说明仍基于此前资料，更新中。”

通知中默认不出现成员姓名、病名、指标数值或报告文件名，只显示“健康资料处理完成”“有事项待核对”。

# 6. 首次使用、成员和账户

## 6.1 初始化流程

1. 显示“体验虚构看板 / 建立我的家庭档案”。演示独立存储，绝不混入真实工作区。
2. 创建唯一 workspaceId 和本地目录，检查可写权限、空间和版本。默认路径不要求用户手填。
3. 检查 App 管理的 Codex 运行时版本和完整性；缺失时通过明确的运行时管理界面修复，不要求用户装开发工具。
4. 用户点击“使用 ChatGPT 登录”；交给 Codex 发起浏览器流程，等待完成事件后读取账户和模型能力。
5. 创建第一位成员，可继续添加其他成员。保存不要求 AI 在线。
6. 选择报告收件箱。推荐每位成员绑定一个子目录，也可绑定一个公共“待归属”目录。
7. 设置每日时间、是否托盘驻留、是否启用开机启动；显示尚未处理的新文件数量。
8. 明确授权自动处理的范围、服务商、用途和账户用量。用户启用后才开始自动发送。
9. 可以点击“现在处理已有报告”，否则等首个计划时点。导入历史资料与以后新增资料采用同一流程。

**断网、拒绝登录或没有额度时：**允许建档、导入本地资料和浏览演示；相关 AI 任务停留在等待状态，不用弹窗阻塞整个 App。

## 6.2 成员资料

最小必填项仅显示名。可选关系、出生日期/出生年份/年龄及其截至日期、与解读有关的性别信息、既往史、过敏、正在使用的药物和用户补充。不存在的信息保留未知，不要求填写身份证或完整住址。

personId 由 App 生成，不由姓名生成。昵称变化不改变关联。医疗相关背景变更触发该成员派生说明失效；纯显示信息变化不重新调用 AI。

未成年人也可以作为档案成员，由已获授权的成年管理员处理；不创建未成年人的 Codex 登录账号，不要求儿童与 AI 对话。

## 6.3 成员归属规则

确定性优先级：用户在 App 明确指定 > 已确认绑定目录 > 用户已核实的报告身份映射。模型从正文提取的姓名只能作为匹配证据。

如果正文身份与目录绑定冲突，必须停留在待归属，不能直接相信目录。重名、多个成员、不同身份混在同一文件时不得自动合并；可把文件留作多主体未归属资料并要求拆分或确认。

公共待归属目录默认只登记，未获“允许为归属识别发送该文件”授权时不得先把文件发云端。默认推荐绑定成员目录来减少这一额外交互。

## 6.4 账户与费用边界

只实现 Codex 管理的 ChatGPT 登录；首版不出现 API Key 输入框。App 从协议取得认证状态，而非解析 auth.json。账户信息只显示必要的掩码标识、连接状态和服务端提供的用量信息。[S03][S04]

产品文案必须是“可使用账户包含的 Codex 权益，无需单独配置 API Key”，不能是“无限免费”。额度用尽后，账户可能使用已购买 credits 或账户自己的自动充值机制；App 的阈值暂停不是支付系统级绝对阻断。[S05][S06]

默认额度策略：任务开始前查询可用状态；明确耗尽时暂停；对于正常返回的百分比，用可配置安全余量控制新的后台任务。若额度状态缺失或查询失败，自动任务进入“额度状态待确认”，不自作主张承诺零额外支出；用户可通过一次明确选择允许在未知状态下继续。新 turn 前再次检查，不循环重试耗尽错误。

不自动购买 credits、消耗额外付费加速选项、更换账户或转到付费 API。不要求用户关闭安全设置。用户退出账户后暂停 AI，但保留本地可读档案。

# 7. 多格式导入与证据构造

## 7.1 输入兼容矩阵

| 输入 | 首版行为 | 证据定位与限制 |
|---|---|---|
| PDF，含文字层 | 本地读取页数和文本，同时渲染需要视觉确认的页 | 页码 + 文本片段，必要时布局坐标；不得只依赖可复制文字的排列顺序。 |
| PDF，扫描件 | 本地逐页渲染，分块交给 Codex 视觉 | 原 PDF 页码，记录每页是否可读和处理覆盖。 |
| JPG/JPEG、PNG | 本地修正方向、保留原件、生成任务用副本 | imageId + 图内可验证区域；未经验证的模型框只作候选。 |
| HEIC/HEIF | 通过内置已验证解码组件转换为可发送图片 | 保存原件、转换版本与关联；不能依赖 Windows 已安装付费编解码器。多图容器不能悄悄只取第一张。 |
| DOCX | 解析正文、表格、脚注及内嵌图片，图片交 Codex | 使用 documentBlockId/tableCellId/embeddedImageId；原文件不保证稳定页码。 |
| DOC | 本地兼容组件转为安全中间格式，再按文档处理 | 记录转换产物哈希与版本；衍生 PDF 页码标明“转换后页码”。 |
| TXT | 自动检查 UTF-8/BOM，必要时识别编码并展示预览确认 | 行号 + 字符区间；解码不可靠时不默默替换乱码。 |
| 手动结构化记录 | 用户选择成员和日期后直接保存为用户记录 | recordId + revision；不需要模型来确认一个已明确填写的值。 |
| 手动自由文本 | 先保存不可变原文，后进入 AI 整理流程 | 原文段落/字符区间；保留 user_reported 来源。 |

不支持：`.docm`、可执行文件、宏模板、DICOM、加密压缩包、目录中的任意网页/脚本。仅改扩展名不得绕过文件类型判断。

## 7.2 机械处理与模型理解的边界

App 负责文件解码、页码、哈希、尺寸、文档块、图片转换、来源 ID 和分片；Codex 负责图像/文字语义理解和结构化候选提取。默认不对图片使用额外 OCR 服务，也不把本地 OCR 当作不可见的替代路径。

图像发送使用实际图片输入，而不是只把文件名、路径文本或零散 OCR 文字给模型后声称“已读图”。当前 App Server 文档给出了本地图片输入能力，具体字段以锁定运行时生成的 schema 为准。[S03]

默认任务图片长边约 2400px，文字过小时可对原图分块；这是初始工程参数，须通过金标准样例验证后冻结。保留全页缩略和细节切片映射，禁止裁切后忘记覆盖边缘区域或表格续页。

## 7.3 Word 兼容的实现要求

DOCX 主路径不要求 Microsoft Word。首选本地语义解析与内嵌图片提取；解析库输出的 HTML 不可直接注入 Electron 页面。禁用外链、文件外部引用和宏，按白名单把内容转换成内部文档块 DTO。[S14]

旧 `.doc` 使用独立转换适配器，优先验证 LibreOffice headless。转换器应由项目打包或在用户明确选择后通过 App 下载固定版本，不依赖用户使用终端安装。运行时须独立 profile、禁止宏与外部资源更新、不提供 UNO 监听服务、无 shell 字符串拼接。[S15]

G0 必须验证三个目标架构的可分发组件、体积、签名、许可义务、进程退出和恶意文件限制。可采用按需兼容组件减少基础包大小，但 UI 必须提前说明首次 DOC 导入需下载组件。若没有通过验证，标记“DOC 支持尚未达到 Beta 门禁”，不能把需求无声降成“只接受 DOCX”，也不能要求上传在线格式转换网站。

DOCX 版式不支持或只含扫描图片时优先转为页面证据；转换失败保留原件并进入例外队列，不输出一份看似完整的空报告。

## 7.4 文件安全与大小

设计基线：单文件 100MB；单次导入最多 100 个文件；单份报告超过 200 页转大任务提示或要求分批，不崩溃、不静默截断。AI 发送每次分片页数和字节上限在 G0 依据真实模型能力冻结，默认从 4 页/组开始。

文件登记读取真实类型及魔数；DOCX 解包限制累计解压大小、条目数与目录层数，拒绝路径穿越、符号链接、外链和压缩炸弹。图片限制解码像素数（初值 80MP），有资源超限时提示而非无限分配内存。

不在原目录执行工具，不修改或删除用户的原件，不跟随符号链接、Windows junction 或越出授权目录的别名。转换失败或文件被占用应显示原因，不能把错误归为“没有异常数据”。

## 7.5 来源覆盖

每份资料生成 SourceManifest，至少含：原件哈希、派生文件哈希、页数或块数、处理分片、每个分片的输入 ID、可读性、遗漏说明、转换器版本和正文/图片的证据映射。

PDF 10 页必须有 10 页覆盖状态；“未见指标”也需要对应页的判定。低质量页不能从分母消失。DOCX 的段落和表格用块计数，不能伪造“第 1 页”作为所有字段来源。

所有 ID 由 App 分配；模型只能返回合法 ID 或局部候选键，不能为不存在的报告生成“证据”。

# 8. 报告收件箱与文件发现

## 8.1 目录授权与映射

一个工作区允许多个受控收件箱；首版 UI 推荐“一个根目录 + 成员子目录”，但每条绑定在数据库中保存真实路径和 personId，不以文件夹当前显示名作为唯一身份。

新增绑定必须通过系统目录选择器，向用户显示递归范围、关联成员、是否包含现有文件、是否启用每日发送。允许只发现不自动处理。首版不监控整个用户主目录、下载目录的所有内容或外部 Agent 的任意工作目录。

收件箱与内部 `vault/`、`staging/`、`backups/`、Codex HOME 和软件代码目录不能交叠，以防输出触发自身导入。禁止把网络盘或云同步占位文件当作稳定本地对象；首版正式支持本地目录，其他路径提示不在验证范围。

## 8.2 发现流程

`FS event → debounce → 稳定性检测 → 类型检查 → 哈希 → 不可变拷贝 → 登记待处理 → UI 事件`。

设计初值：debounce 500ms；大小和 mtime 连续 5 秒稳定后尝试读取；读取前后 stat 与流式哈希一致，必要时再次重试。仅使用 `awaitWriteFinish` 不足以证明拷贝完整，必须在建立对象前后再确认。[S12]

发现后的工作只做本地登记和安全预处理，不启动 Codex。文件在稳定后通常应在 10 秒内出现在 UI；此为性能目标，不把巨型文件哈希时间伪装成固定保证。

## 8.3 去重与改名

字节哈希相同：同工作区对象只保留一份物理副本。同成员重复来源路径新增 provenance，但不创建新的报告/指标；跨成员发现相同文件，先检查归属，不能因为已缓存提取结果而自动应用给另一人。

文件名相同但字节变化：视为新 SourceRevision，不能覆盖已存原件。相同内容改名：更新观察来源，不重做 AI。编辑软件的原子替换：以最终稳定内容为准。

近似重复扫描、同内容不同压缩等仅标记“可能重复”，不能靠近似哈希自动删除或合并临床记录。

## 8.4 对账扫描

文件系统事件不是唯一事实来源。必须在启动、恢复唤醒、重新取得目录权限和每日批次前执行对账；应用运行期间每 15 分钟进行轻量目录对账，未变化文件不重新全量读字节。

应用关闭期间新增的文件，应在下一次运行后发现。目录暂时不可用时显示“连接不可用”，保留绑定和历史；不把暂时离线解释为用户删除全部报告。

从收件箱移除原文件，不删除已归档对象。用户在 App 删除报告时才进入资料删除流程。显式删除后记录导入抑制 tombstone，避免原文件仍在收件箱导致马上再次导入；界面提供“重新允许导入”。

## 8.5 用户动作

支持按状态、成员和批次筛选；批量分配成员；立即处理所有就绪文件；只处理选中项；忽略单文件；暂停目录；重试失败项。

“忽略”不等于删除原件；“暂停自动处理”不隐藏已有待处理任务；“重新处理”不绕过版本冲突和已核实字段保护。

# 9. 每日调度、后台与恢复语义

## 9.1 运行承诺

每天本地时区 20:00 作为默认时点，可配置。应用正在运行或驻留托盘、设备醒着、授权和账户有效、额度允许时，触发一个自动批次。

**不承诺 App 完全退出、电脑休眠、断电或用户未登录 OS 时仍能执行。**首版不安装独立守护服务，不主动唤醒电脑，不为了处理报告阻止设备正常休眠。

错过执行时点：下一次启动或恢复时，最多合并补跑一次，把当前就绪积压纳入；不会补发过去 10 天的 10 个空批次。批次启动前 UI 显示正在补处理，不冒充在 App 退出时已完成。

## 9.2 调度参数

```text
schedule.enabled: boolean
schedule.localTime: HH:mm               # 默认 20:00
schedule.timeZoneMode: follow_system
schedule.missedRunPolicy: coalesce_latest
schedule.pauseOnUnknownQuota: true
schedule.startOnLogin: false
schedule.stayInTray: 用户首次明确选择
schedule.autoBatchMaxFiles: 100
schedule.aiConcurrency: 1
```

这些配置是本产品字段，不是 Codex 协议。首次授权后后台处理不反复弹“是否上传”提示，但更换目录、账户或外发处理范围需要重新确认。

## 9.3 日程去重与快照

以工作区、计划身份和对应本地执行日期形成稳定 slotKey，保存 scheduledAtUtc、时区和 scheduleRevision。数据库用唯一约束保证同一 slot 只创建一个自动批次。

手动批次不占用每日 slot；但手动与自动共同从同一队列领取文件，文件级 lease 和 idempotencyKey 防止重复执行。20:00 时已在手动处理中，自动批次只领取尚未被占用的资料或等待合并，不启动第二套相同任务。

每个批次在开始时冻结 sourceRevision 列表和 cutoff 时间。批次执行途中发现的新文件，留待下一批或手动触发；不让一个批次因持续新增永远无法完成。每日上限未处理完的文件留队列并清晰说明。

改变每日时点或时区时重算下一时点。已执行的本地日期不得因为时钟回拨再运行一次；跨日期跳变合并补跑，保存最近自动运行记录避免重复。夏令时缺失时点取当日第一个有效时刻，重复时点只取一次。必须使用可测试的时钟与时区工具，不用固定的 24 小时 `setInterval` 代替日程。

## 9.4 前后台生命周期

关闭窗口后是否驻留在首次关闭时明确告知并记住。托盘菜单：打开看板、待处理数量、立即处理、暂停自动处理、退出。

“暂停自动处理”停止新自动批次；用户可选择同时暂停队列。当前原子提交不被中途打断；AI turn 的取消通过协议执行，已提交事实仍保留。

真正退出：停止领取任务，尝试中断活跃 turn，保存检查点与可恢复状态，终止属于本 App 的子进程；不得杀死用户自己的 Codex/Office 进程。OS 关机时间不足时使用安全恢复路径，而不是依赖一定能收到完成回调。

Electron 的 suspend/resume 等系统事件可用于这些行为；最终调度决策依据持久记录和当前时钟，而不只依赖一次事件。[S11]

## 9.5 调度伪代码

```text
onLaunch / onResume / onTimer / onScheduleChanged:
  reconcileAuthorizedFolders()
  if !consentValid or !scheduleEnabled: return
  slot = determineLatestEligibleUnprocessedSlot(clock, zone, scheduleHistory)
  if slot is none: return
  transaction:
    createOrGetAutomaticBatch(slot.uniqueKey)
    claimStableReadySources(cutoff=now, limit=maxBatchFiles)
  worker.runIfAccountAndQuotaPermit()
```

不是在每次打开页面时重新执行 AI。空队列只记录 slot 已检查，零模型调用；同一天稍后新增的文件保持“明日处理 / 立即处理”状态，不以轮询变成全天连续调用。

# 10. 持久化 AI 工作流

## 10.1 阶段与两次独立提交

```text
发现 / 用户导入
  → 本地预处理与归属
  → 分片提取
  → 事实复核与确定性校验
  → [自动接纳 / 例外] → 事实事务提交
  → 按成员构造当前资料快照
  → 综合分析
  → 后续事项与生活指南
  → 派生内容复核与安全检查
  → [自动接纳 / 局部例外] → 派生快照事务提交
  → UI 更新、本次变化、后台摘要通知
```

事实与分析分开提交。清晰的报告事实通过校验后可以展示，即使后续分析暂时失败。此时界面应标明分析尚未更新，不能让旧分析伪装成基于新报告。

一次技术错误不影响其他成员或同批中已通过的报告。新派生快照完整且通过验证后才替换当前派生快照；显示中的版本要可追溯。

## 10.2 阶段定义

| 阶段 | 输入 | 输出 | 允许的失败结果 |
|---|---|---|---|
| Normalize | 固定原件、格式与类型 | SourceManifest、页面/块/图片 | 格式不支持、密码保护、文件损坏、组件缺失 |
| Identify | 用户/目录归属和报告身份候选 | personId 或归属例外 | 多主体、姓名冲突、无法确认 |
| Extract | 本分片证据、最小身份上下文、版本化提取规则 | ExtractionCandidate | 不可读、疑似遗漏、未知数值 |
| ReviewFacts | 原证据、独立提取/复核规则 | FieldReview、CoverageReview、ConflictList | 不一致、无法确认 |
| AcceptFacts | 候选 + 复核 + 本地规则 | FactChangeSet、自动决策记录 | 用户例外、版本变化 |
| Analyze | 该成员当前事实快照、必要背景、覆盖清单 | AnalysisCandidate | 上下文不完整、来源缺失、拒绝 |
| GenerateGuidance | 已验证的分析候选、事实、通用教育来源 | SuggestionCandidate + LifestyleCandidate | 缺证据、超出范围 |
| ReviewDerived | 原事实、分析、建议和生活指南 | 支持项、纠正项、越界项、时效性 | 需要局部修正或省略 |
| Publish | 当前版本检查 + 有效候选 | PublishedSnapshot、ChangeSummary | 并发修改、数据过期、磁盘问题 |

## 10.3 提取与复核策略

清晰报告默认执行主提取和一个独立上下文的事实复核。对身份、日期、数值、比较符、单位、异常标记、报告参考范围和页覆盖做重点核对。

可先让复核者从原证据独立提取关键字段，再由 App 与主提取匹配；在存在差异时，把冲突字段和来源交给一次定向复核。不为每个正常字段逐项无限追加模型调用。

若实现选择“复核者可见候选结果”的模式，要在处理记录中标明，不宣称完全独立盲审。同模型不同线程降低上下文污染，但不代表医学独立性或无共同错误。

自动修正只限格式、明确单位表示和可被证据验证的纠错。未确定的数值返回 null + 原文 + issue；不能“为了通过 Schema”填 0、造一个日期或补一个参考范围。

## 10.4 分析及一般建议

分析根据当前成员全部可用的结构化事实工作；只对变化相关的原始页做按需附加，不重复发送整家所有历史 PDF。上下文超限时按主题/器官切分，返回实际覆盖的时间和数据范围，不能静默截断后声称分析完整。

默认不使用网页搜索获取“新医疗建议”。可在程序中提供经过维护、标注出处和版本的一般健康教育规则集；不允许引用模型编造的研究、指南或 URL。报告中的医生复查安排可原文归纳；AI 新提事项应明确为待咨询，不给具体治疗方案、处方药调整和营养补充剂剂量。[S20]

一般生活指南可以解释日常原则和低风险行动起点，但应受既有报告限制和数据充分度约束；资料不足时不做个性化医疗判断。疾病、危急值和紧急症状不由系统自动诊断；原文明确标记“危急”时，可以突出该原文并提示尽快向专业人员核实，而非生成新危急阈值。

## 10.5 调用与重试预算

默认每个提取分片：主提取 1 次、复核 1 次；仅有差异时允许 1 次定向修正。按成员批次：分析 1 次、建议+生活指南可以合并为一次有明确双输出的任务、派生复核 1 次。

这是调用上限设计，不是实际订阅消耗估价。成功提取的缓存用输入哈希、任务规则版本、模型和输出契约键定位；改变模型不自动重跑所有已接纳历史，只有显式重分析或质量修复任务才重新计算。

网络瞬断的协议重连和结果修正分开计数。指数退避最多 3 次；401 转待登录，明确额度耗尽转待额度，内容拒绝保留 reason，不通过改提示反复规避拒绝。超时后必须先核对 turn 状态，不能把未收到回应等同于服务端未执行。

## 10.6 任务进度

UI 显示“已完成 4/10 页”“正在核对”“已保存资料，正在更新分析”等可计算进度。模型正在处理时用不确定进度条，不伪造 83% 或剩余 12 秒。

不用模型的 `plan` 自由文本决定 App 状态，也不用一句“完成”触发保存。只有协议终态、完整候选输出、运行时校验和接纳策略均满足，才转入可提交状态。

# 11. 全自动接纳与例外规则

## 11.1 自动接纳不是临床审核

新系统使用 `AcceptanceDecision`，而不是让 Agent 伪造人工签字的 `approvedBy`。自动记录为 `actor=policy`、`method=auto`，关联规则版本、输入哈希和复核任务；用户处理后则 `actor=user`、`method=user_resolution`。

UI 统一区分：**报告原文记录、用户补充、AI 整理、AI 复核、用户核对、报告中的医生意见**。不能把本地用户点击“完成复查”变成“医生已确认某个诊断”。

## 11.2 可自动入库的必要条件

所有条件同时满足：成员归属一致；来源覆盖无未声明缺失；关键事实有有效定位；Schema 与引用关系通过；复核没有未解决关键差异；数据未覆盖用户锁定值；输入版本仍是当前版本；不包含无依据诊断、处方或伪造来源；符合当前已授权外发范围。

模型自评置信度不作为唯一接纳条件。暂以明确规则和金标准回归控制质量；以后要使用分数阈值，必须先有校准证据。

## 11.3 例外分级

| 级别 | 示例 | 系统行为 |
|---|---|---|
| 阻断归属 | 姓名不符、多个成员混在同文件、重名无法确认 | 不把任何事实写到某成员；登记并要求归属确认。 |
| 阻断字段/事件 | 关键数值看不清、日期会影响趋势但无法确定、单位冲突 | 保留不确定字段；必要时整条测量暂不进入趋势；其他独立已验证部分可接纳，并显示部分完成。 |
| 阻断覆盖 | 需要替换用户已核实值、同次检查同指标互相矛盾 | 展示修改前后与证据；禁止最后写入者胜出。 |
| 可接纳警告 | 缺非必填机构名称、无参照范围、部分非关键正文不可读 | 原样保存已知部分，标明限制；不得默认异常标记为 false。 |
| 派生安全问题 | 分析包含因果过度推断、给出处方、出现假引用 | 一次定向修正；仍不合格则省略相关派生段落并保留事实。 |
| 技术等待 | 额度、网络、登录、缺转换组件 | 队列等待，不把它当作用户健康风险。 |

## 11.4 用户处理方式

例外页只提供结构化动作：选择成员、输入可验证值、保留未知、说明原因、暂缓。无需输入完整提示词。用户修正作为独立 revision，保留原提取与原文。

用户可撤销一次错误修正或退回上一个有效版本；这会触发依赖失效，不自动删原报告。允许直接将资料标记“仅归档，不纳入分析”。

正常无例外路径自动更新，不增加总确认弹窗。涉及删除、重置工作区、导出分享、退出时取消任务等有副作用的用户动作，仍保留操作确认；它们与 AI 阶段审批不是同一回事。

# 12. 增量、去重、版本与失效

## 12.1 稳定对象与版本

workspaceId、personId、sourceId、reportId、encounterId、measurementId 使用应用生成的随机稳定 ID，不以姓名或日期拼接。源文件字节用 SHA-256 去重；临床实体 ID 与哈希不混用。

原件不可变；修改文件生成新的 SourceRevision。指标修正生成 ObservationRevision，旧值被 supersede 但不删除。用户补充和临床报告事实分别记录来源。

## 12.2 同日、同次与重复

同一天不是合并条件。只有已确认 encounter linkage 和事件日期、机构/来源、报告关系一致时才合并。默认宁可两条可合并事件，不要误把上午体检和下午就医覆盖为一次。

同一事件中同名指标若来自不同标本、左右眼、检测方法、采样时间或单位，保留为不同测量。不能 `Map[standardName]=value` 覆盖。

## 12.3 依赖签名

每位成员的临床上下文 hash 与显示配置分开。每个派生结果保存：factRevision、clinicalContextRevision、相关来源集合哈希、promptVersion、rulesVersion、modelId、schemaVersion。

| 变更 | 需要失效 |
|---|---|
| 昵称、头像、排序 | 仅视图，不重提取或分析。 |
| 该成员新增报告 | 该成员相关分析、事项及生活指南；其他成员不变。 |
| 该成员单位或关键数值修正 | 对应事实相关趋势与派生结果。 |
| 报告归属换人 | 原成员移除引用后的结果和新成员加入后的结果都重算；需要显式确认。 |
| 生活习惯变化 | 相关派生说明，可不重读历史报告。 |
| 模型版本更新 | 不自动推翻已接纳事实；新任务用新版本，显式重分析才更改旧说明。 |
| 接纳规则发现缺陷 | 通过范围明确的质量修复任务重新评估，展示影响，不偷偷重写全库。 |

## 12.4 增量发布

以成员为单位制作 ChangeSet：新增、替换、保留、冲突、忽略、失效。每个提交带 expectedRevision，提交时执行 compare-and-swap；不匹配则重建基于最新事实的候选，不自动覆盖。

流程推荐：文件复制到临时位置 → 哈希确认 → 原子移入对象存储 → DB 事务登记 → AI 候选 → DB 事务接纳事实 → 派生结果候选 → DB 事务更新派生快照。未被 DB 引用的残留对象经安全回收，不因为短暂写入失败删用户原件。

模型输出即使含有效 Schema，也不能自己指定写入数据库的位置。所有正式写入经过核心服务。

## 12.5 “至少一次执行，恰好一次提交”

远端调用与本地事务无法做到一个跨网络原子事务。设计目标是允许重试执行，但由唯一约束、任务输入签名和 commit key 保证同一逻辑结果不会重复生效。

Codex thread/turn ID 只是执行收据，不是健康数据主键。线程丢失后可以重建任务，但提交仍必须查本地结果；不能只靠是否存在 threadId 判断是否已经处理过。

# 13. 健康信息展示规则

## 13.1 事实、解释、状态分开

建议 DTO 分成三组：事实 Observation、资料质量 DataQuality、派生说明 Assessment。不要把一个 `normal/attention/alert` 充当所有含义。

资料质量可以是 complete/partial/insufficient；派生结果可以 current/stale/pending/failed；报告异常标志可以 high/low/positive/negative/normal/unknown，并保留原文。

全家总览不从“异常指标数量”计算健康总分。器官卡片的“需关注”应对应有来源的说明，不代表诊断，且展示资料时间。

## 13.2 趋势规则

原始值与可比较数值并存。缺失值不变 0，`<0.01` 不变精确 0.01，阴性不变 0，定性变化不用数值折线。单位转换必须基于明确的指标和转换规则，记录原单位和转换版本；不能让模型在没有记录时自由换算。

历史点需要真实日期。未知日期排到独立分组；年份精度不能冒充某日。图表点之间有缺失时断开，默认横轴使用真实时间间隔；采样方法、单位、空腹状态等不可比时分组或明确标识不比较。

每次报告的参考范围独立保存，不用最新范围回填过去。不得用最新值的异常状态给全部历史点着色。箭头使用中性色表示上升/下降，健康意义由有证据的解释单独表达。

## 13.3 诊断、病史与药物

从报告抽取的诊断保留 `reportedBy=clinical_document` 和来源位置；“confirmed”只反映原文明确状态，而非 AI 验证。原文是疑似或待排除时不能升级；“resolved”需要后续明确来源，不能因为指标变正常推断疾病已治愈。

用户补充的病史和用药单独标记 user_reported。允许记录用药名称及用户填入/报告写明的剂量，但不主动建议增减、开始或停药。发现记录冲突只提示核实。

## 13.4 后续事项

ActionItem 独立于某次分析快照长期存在，必须有 actionId。来源分为 clinician_document、user_created、ai_proposed；状态分为 proposed、discussed、planned、completed、dismissed。医生是否确认是另一个带证据字段，不能用完成状态替代。

重新生成建议时根据稳定来源和事项含义做关联，不将用户已完成的事项重新置为待办。只有明确新证据支持新的周期任务时才创建新实例，且显示“新一轮”。

时间字段允许原文“半年后复查”，只有基准日期可靠时才能计算提醒日期；首版可展示计算后的参考日期但不自动通知，保留原文与计算依据。

## 13.5 导出摘要

首版可导出用户选择成员和日期范围的 PDF/HTML 资料摘要，以及结构化 JSON。摘要使用当前已保存内容和固定模板，不为导出再次生成一套未复核医疗解释。

导出前显示包含内容及隐私提示；默认不自动附原始报告。导出不等于上传或发送，产品不自动代用户发送给医生或家人。

# 14. 本地数据模型与契约

## 14.1 建模原则

SQLite 是首版系统状态与正式数据的唯一事实来源；原始大文件在对象存储。使用外键、唯一约束、事务和索引。所有医疗字段允许未知但不能用默认健康值填充。

数值原文永久保留；用于精确比较的十进制以规范 decimal 字符串存储，绘图时才转换为有限数值。所有时间戳用 UTC；临床日期另存日期字符串与精度，不能仅用 UTC timestamp 表达日级检查日期。

字段规范由 `packages/contracts` 统一维护。模型可返回候选局部键，最终 ID 和系统状态由 App 决定。AI Schema 不包含 OAuth、任意输出路径、SQL 或“已批准人”的可控字段。

# 15. Codex App Server 集成规范

## 15.1 官方能力与验证边界

官方文档支持通过 App Server 将认证、线程、turn 和流式事件接入产品，并可从特定 Codex 版本生成协议类型；文档同时对部分功能以及 App Server 命令/传输的生产成熟度有警示。[S03][S16]

因此本项目交付目标是经过明确验证的 Beta，不宣传长期协议兼容或医疗生产级保障。采用 stdio 并不自动消除文档中的成熟度风险。

**G0 必须先验证：**三目标平台运行时能启动；浏览器登录可用；本地图像确实被模型读取；结构化输出可解析；取消与恢复可靠；工具权限满足本产品限制；账户状态和额度异常可识别。验证不通过不得用模拟 API 宣称集成完成。

## 15.2 运行时分发

默认捆绑经过校验的 Codex 运行时及该平台所需辅助文件。只复制一个可执行文件而漏掉 Windows 沙箱 helper 等组件不算完成。也可采用 App 内的固定版本修复下载，但首次安装在没网络时仍应能浏览演示和已有数据。

在 `runtime-lock.json` 记录版本、来源、platform/arch、每文件 SHA-256、schemaHash、所用配置和已验证能力。不要运行 PATH 上未经确认的 `codex`，也不要求用户全局安装 Node、Python 或 Codex CLI。

更新运行时必须经过兼容测试后随应用版本发布或由受信清单更新；忙碌期间不替换二进制。遵守上游许可、版权声明和再分发条件，不冒用官方品牌或宣称官方认证。

## 15.3 协议客户端

使用 `spawn(executable, args, { shell: false, ... })` 和 stdio。进程属于本 App 生命周期。使用有界缓冲、UTF-8 增量解码、按帧读取和 request ID 关联；一次 stdout chunk 不一定是一条完整消息。

按所选运行时 schema 处理请求、响应、通知与**来自服务端的请求**。不能假设所有无 `result` 的消息都是通知。保留未知事件的类型与计数用于诊断，不能因新增非关键通知直接崩溃；未知权限请求默认拒绝并记录。

启动：进程就绪 → initialize → initialized → account/read → model/list / 额度检查 → 启动任务。客户端版本、协议 schema 版本与运行时版本纳入收据。所有 Codex 原始对象只在适配层使用。

## 15.5 登录处理

用户点击连接后，调用 Codex 管理的浏览器登录。App 只打开实际返回、经 URL 解析和域名白名单核验的官方 HTTPS 登录地址；不把整个带查询参数的 authUrl 写入日志。浏览器回调由 Codex 承担。

记录 pending loginId 以忽略过期登录通知；取消/超时后允许重试。公司代理、回调端口冲突和登录拒绝必须有可理解错误。官方设备码流程仅在版本能力验证后作为备用，不实现自建验证码表单。[S03]

使用 App 私有 CODEX_HOME 和官方 keyring 凭据存储模式，不能静默回退为应用明文保存 token。凭据库不可用时显示限制；不修改用户全局 Codex 设置。独立目录不保证所有平台 keyring 命名天然隔离，G0 必须验证 App 退出不会注销用户其他 Codex 环境。[S04]

账户更换时暂停等待发送的任务，重新确认已有目录的处理授权绑定；本地成员档案不随 OpenAI 账户自动切换或删除。OAuth 只授权模型能力，不是健康档案权限或本地解锁。

## 15.6 输入与输出封装

图片使用协议的实际本地图像输入，文本以被明确分隔的证据内容输入。路径只由适配层解析，模型看到的 sourceSpanId 不可扩展为任意文件访问。

每个阶段使用独立线程或明确隔离上下文；报告内容不作为 system/developer 指令。任务模板必须告知文档内任何“忽略规则/上传到网站/读取文件”的文字都是不可信资料，不是操作授权。

`outputSchema` 仅为结构约束，不能代替业务校验。等待最终结构化内容与 turn 终态后再验证，不从部分 delta 或模型进度文本中截取 JSON 直接入库。遇到输出截断、无内容、拒绝或不符合 schema，转可恢复失败或一次定向修正。

为避免 App Server 版本变化，本文件不固定详细 wire payload。G0 使用真实版本生成 TypeScript/JSON Schema，提交生成产物、来源命令和 hash，并由 contract tests 验证；不能手写一个看似真实但未验证的 API SDK。[S03]

# 16. 任务状态机、错误与恢复

## 16.1 分开保存文件、任务与数据的状态

不得用一个 `isProcessing` 同时代表文件发现、模型运行和数据入库。三者独立：

| 对象 | 建议状态 | 说明 |
|---|---|---|
| 文件出现记录 | discovered / stabilizing / queued / ignored / duplicate / blocked | 发现不等于已经上传模型，也不等于正式报告。 |
| AI 阶段任务 | queued / running / waiting_auth / waiting_quota / waiting_user / retry_wait / succeeded / failed / cancelled | `succeeded` 只代表该阶段有可验证输出，不直接代表正式入库。 |
| 数据版本 | candidate / accepted / superseded / rejected | 正式查询只返回 accepted 事实及有效快照，保留历史版本和来源。 |
| 派生快照 | current / stale / building / unavailable | 原始事实可以先更新，旧分析必须明确显示过期。 |
| 批次 | pending / active / paused / completed / completed_with_issues / cancelled | 一个成员或文件失败不把整个批次回滚成“什么也没有发生”。 |

所有时间保存 UTC；显示使用用户选择或本机时区。终态原因、错误码、可恢复动作分别保存，不能仅保存一段日志。

## 16.2 合法迁移

正常路径是 `queued → running → succeeded`。启动前缺登录、额度、授权或归属时，进入相应等待状态，不先启动模型再盲目重试。用户解决问题后，重新检查依赖版本，再返回 queued。

running 遇到暂时网络错误可以进入 retry_wait；遇到用户取消进入 cancelling 的内部协调过程，收到中断终态或确认子进程结束后写 cancelled。若输出已经原子提交，应返回“已完成；后续阶段已取消”，不能把已落盘数据说成取消成功且未保存。

成功任务不可修改为 running。重试创建新 attempt，并关联原 job；依赖变化则创建新 job 或新任务签名，而不是复用旧批准。

## 16.3 租约与幂等

每个 running job 保存 `leaseOwner`、`leaseExpiresAt` 和 heartbeat。设计默认：heartbeat 每 10 秒，租约 90 秒；恢复时租约过期仅表示需要核实，不能直接断言旧模型任务没有运行。

App 使用单实例锁；SQLite 是唯一正式写入入口。恢复顺序：读取持久化任务 → 确认本 App 拥有的 Codex 进程与实际 turn 状态 → 能恢复就接续 → 无法确认则标记 interrupted → 在版本和幂等键检查后重试。

数据库唯一键必须阻止同一个 `inputSignature + stage + targetRevision` 的结果重复发布。模型调用可能因为断线而重复消耗额度，本方案只保证正式数据的重复提交可被阻止，不承诺模型调用在所有故障下恰好一次。

## 16.4 错误码与界面动作

| 错误码 | 用户提示 | 默认动作 |
|---|---|---|
| AUTH_REQUIRED / AUTH_EXPIRED | 需要连接或重新登录 Codex | 暂停 AI，保留队列和本地档案。 |
| QUOTA_UNAVAILABLE / QUOTA_EXHAUSTED | 无法确认额度／当前额度不足 | 等待，不循环重试，不切换付费 API。 |
| CONSENT_REQUIRED | 新目录或处理范围需要授权 | 显示范围确认，不自动发送。 |
| PERSON_CONFLICT | 报告归属存在冲突 | 打开成员选择与原始证据。 |
| FILE_UNSTABLE / FILE_INACCESSIBLE | 文件仍在写入／暂时无法读取 | 稍后本地重试，不调用模型。 |
| UNSUPPORTED_FORMAT / PASSWORD_REQUIRED | 暂不支持／文件受密码保护 | 可跳过或导入解密后的副本；不破解密码。 |
| CONVERTER_UNAVAILABLE | Word 兼容组件未就绪 | 在 App 内引导安装已验证组件；不要求执行命令。 |
| INPUT_LIMIT_EXCEEDED | 文件或批次超过处理范围 | 分批、缩小范围或选择页面，不静默截断。 |
| MODEL_REFUSAL | 当前内容未能通过模型处理 | 留存状态；不得以改写提示绕过拒绝。 |
| OUTPUT_INVALID / OUTPUT_TRUNCATED | 返回内容不完整或格式异常 | 受限重试，仍失败则等待人工。 |
| EVIDENCE_MISMATCH | 结果与来源或复核不一致 | 进入待核对，不自动保存争议项。 |
| STALE_INPUT | 处理期间档案已发生变化 | 舍弃旧发布意图，按最新版本重新排队。 |
| UNSUPPORTED_TOOL_REQUEST | 本次任务请求了未开放的能力 | 拒绝该请求并停止或有限重试。 |
| STORAGE_FULL / STORAGE_FAILED | 无法安全保存本地资料 | 停止正式提交，保留可恢复输出。 |
| RUNTIME_INCOMPATIBLE | AI 运行时与应用版本不兼容 | 不执行真实任务，提供修复入口。 |

错误详情不得包含 token、完整 authUrl、报告正文、真实路径或身份证号码。显示的短文件名也应只出现在 App 内，不进入系统通知和默认诊断包。

## 16.5 超时与资源默认值

握手默认 20 秒；登录等待默认 10 分钟但允许用户取消；普通阶段软超时 5 分钟、硬超时 15 分钟，是**可配置运行限制，不是向用户承诺的完成时间**。大型页面任务需切片，而不是无限延长。

超时后先请求 turn 中断并查询实际状态；等待 10 秒无法结束时，只终止本 App 启动的进程树。不能根据进程名全局杀死其他 Codex。退出、更新或恢复备份时同样使用此规则。

输出正文和事件缓冲设大小上限；超限落到受限的阶段候选文件或停止任务，不使主进程内存无限增长。具体字节上限在 G0 使用真实协议测量后锁定，并写入 runtime compatibility 配置。

# 17. 业务接口与前后端契约

## 17.1 仅暴露业务能力

桌面 Renderer 不直接接触 Node、SQLite、任意文件系统、Codex stdin/stdout 或认证凭据。通过 preload 暴露有类型的最小业务 API，并在 Main 再做运行时校验和发送者检查。[S08]

推荐内部接口如下。名称是产品 API 设计，不是 Codex 官方方法：

| 分组 | 主要方法 | 限制 |
|---|---|---|
| workspace | getSummary / initialize / getSettings / updateSettings | 更新仅允许白名单设置键。 |
| persons | list / create / updateDisplay / updateClinicalContext / archive | clinical 修改触发明确失效；删除另走确认流程。 |
| imports | selectFiles / selectFolder / registerSelection / listOccurrences / assign / ignore / processNow | 文件路径由系统文件选择器产生的句柄登记，不接受 Renderer 任意路径。 |
| inboxes | create / update / pause / remove / reconcile | 每个目录必须有实际授权，禁用危险路径和重叠目录。 |
| jobs | list / get / cancel / retry / pauseQueue / resumeQueue | 只能操作本工作区任务，重试不能跳过校验。 |
| review | listIssues / getEvidence / resolveIssue | 修改带 expectedRevision；不接受客户端声称“已通过”的任意状态。 |
| dashboard | getFamily / getPerson / getOrgan / getTrend / getTimeline | 只查询正式数据和明确标识的过期快照。 |
| actions | list / setStatus / recordDoctorEvidence | 医生证据与完成状态分别写入。 |
| documents | getMetadata / openEvidence / exportSelected | 按 objectId/sourceSpanId 读取，不透传文件路径。 |
| account | getStatus / startLogin / cancelLogin / logout / getQuota | 不返回 access token、refresh token、auth.json 或凭据库内容。 |
| backup | create / inspect / restore / exportEncrypted | 目标目录由系统选择器获取；恢复前需确认。 |
| diagnostics | preview / export | 默认只含脱敏运行信息，预览后由用户保存。 |

## 17.2 返回模型

```ts
type Result<T> =
  | { ok: true; data: T; revision?: number }
  | { ok: false; error: {
      code: string;
      messageKey: string;
      retryable: boolean;
      action?: 'login' | 'review' | 'retry' | 'select_file' | 'settings';
      correlationId: string;
    }};
```

不把数据库异常栈和模型原始输出直接变成用户错误文本。开发日志可以有脱敏栈；产品日志按第 18 章处理。

## 17.3 事件

推送事件限定为 `inbox.changed`、`job.changed`、`review.changed`、`data.published`、`account.changed`、`quota.changed`、`backup.changed`。事件携带 ID、版本和状态，不携带全份报告或 token。

Renderer 收到事件后按版本获取必要数据；启动和恢复可见时进行一次状态快照刷新，避免漏事件导致界面长时间不更新。大数据列表分页，趋势只加载当前指标需要的点。

未来远程 API 可以复用业务 DTO，但首版不为了“将来扩展”提前开放 HTTP 监听、跨域访问或远程写入。

# 18. 隐私、安全与数据处理授权

## 18.1 明确的保护承诺与不承诺

**首版承诺：**不把健康资料上传开发者服务器；不提交到 Git；不放入公开演示或前端静态代码；AI 任务仅发送用户授权范围内必要内容；本地正式文件不向 Renderer 或 AI 任意写入；凭据不进入日志或备份。

**不能承诺：**全程离线推理、无限免费、能抵御已控制当前 OS 账户的恶意程序、上传后远程收回已发送内容、AI 结果必然医学正确。用户选择不做 App 解锁，因此同一已登录 OS 会话中的人可能打开看板。

默认健康 SQLite 和原始文件使用 OS 用户目录权限，不把它宣传成“应用级全盘加密”。操作系统磁盘加密由用户环境决定。首版不增加资料解锁口令；备份导出另做密码加密，不与应用打开混淆。

Electron safeStorage/系统凭据库只保护其实际加密的秘密，不自动加密数据库。Windows 等平台下同一用户上下文的保护边界必须按官方说明理解。[S18]

## 18.2 授权范围

授权记录包含：工作区、处理服务 OpenAI/Codex、登录账户关联标识、资料范围、成员范围、是否允许日程自动发送、版本、时间和撤回时间。账户显示标识仅保存最小必要值；不保存认证令牌副本。

**导入到本地**与**授权发送给 AI**分开。允许离线导入和稍后登录；尚未获上传授权的数据不能因为日程到了而发送。

成员绑定文件夹的授权可以覆盖后续新增文件，但必须在启用时用明确文字说明。新增其他文件夹、改变账户、扩大成员范围、改变模型服务商或引入额外第三方处理器时重新确认。撤回后停止新的上传；已发送的上下文不能被本地撤回动作保证远程删除。

对云推理、账户数据控制以及家庭成员资料授权的说明，参考官方账户使用说明；不要宣称所有订阅默认具有相同的数据保留或训练规则。[S04][S05]

## 18.3 文档不是指令

报告、TXT、Word 内容和手动长文本均是不可信业务数据。它们可能包含链接、代码、隐藏文字或“忽略前面的规则”等句子。

模型只能把这些内容当证据。App 不执行文档中的命令，不自动访问链接，不加载外部图片，不把原文 Markdown 当特权 HTML。医学文本中的“建议访问某网站”不会构成系统网络授权。

对模型输出同样不信任：只接收契约内的候选数据；未知字段拒绝或隔离。输出中给出的本机路径、SQL、脚本、HTML 事件属性、额外数据上传请求不能执行。

## 18.4 进程与内容安全

必须设置 contextIsolation、sandbox，关闭 nodeIntegration；生产 CSP 禁止任意远程脚本；限制 window.open、导航、下载和 openExternal；所有 IPC 验证发送者与参数。[S08]

原始文档通过受控应用协议按 ID 提供，防目录穿越、符号链接和任意文件读取。DOCX 转换的 HTML 必须清洗，不加载外链；更优先提取文本结构到自有组件，不直接渲染未经清洗的生成 HTML。[S14]

Word 兼容组件以独立进程、独立临时 profile 和受限输入输出运行；禁用宏及外部链接更新，限制资源，不读取用户已有 Office/LibreOffice profile。默认不向网络获取文档外部依赖。转换进程同样必须经过恶意样例测试。

## 18.5 存储保留与清理默认值

| 数据 | 默认保留 | 清理规则 |
|---|---|---|
| 正式原始资料与结构化档案 | 用户管理，长期保留 | 删除需明确确认；不因收件箱文件移走而删除。 |
| 已完成任务的页面渲染临时文件 | 7 天 | 可由原始资料重建；与正在运行任务隔离。 |
| 候选失败输出与待核对证据 | 未解决时保留；终结后 30 天 | 用户可清理已终结任务，不删除仍需处理的证据。 |
| 脱敏应用运行日志 | 14 天，另设大小轮转 | 不包含报告正文、完整路径、邮箱或 token。 |
| 任务摘要与数据版本审计 | 与正式档案同步保留 | 仅保存必要动作和来源，不存隐藏推理。 |
| Codex 本地线程与会话资料 | 独立 App 环境；以锁定版本验证为准 | 不能把关闭 history.jsonl 等同于清理全部线程。提供明确说明与受控清理。 |

Codex 的实际记录位置和清理 API/文件生命周期需在 G0、T17 验证。不能直接递归删除正在使用的 CODEX_HOME，也不能把用户独立 Codex 的会话删掉。缺少安全逐会话清理能力时，至少明确哪些记录仍存在、支持在退出引擎后清理本 App 的任务环境，同时保护凭据边界。[S04][S07][S16]

对 SSD、系统备份和云盘副本，不承诺 App 删除等于安全擦除全部历史副本。

## 18.6 诊断与遥测

首版**不接入产品遥测和第三方崩溃上报**。默认诊断包包含应用版本、运行时版本、平台架构、错误码、任务阶段统计与脱敏配置，不包含姓名、报告正文、原始路径、文件名、文件哈希全集、模型上下文、账号令牌或数据库副本。

用户先预览，再选择保存。产品不自动向 GitHub 发 Issue 或上传附件；Issue 模板提醒不要上传真实报告。人工支持需要更多信息时，也只通过用户明确决定的最小资料范围。

# 20. 备份、导出与恢复

## 20.1 首版提供三种操作

**自动本地恢复点：**每日第一次正式数据写入前创建一个一致性恢复点，保留最近 7 个日点和 4 个周点。原始文件不可变且可共享存储；不要把整个大目录每天完整复制。用户看到实际占用和最近可恢复日期。

**手动加密备份：**用户点击导出，选择位置并设置备份口令；导出成员、原始资料、事实、正式派生结果、审计和恢复所需版本信息。不能默认导出 OAuth、Codex 缓存或电脑绝对路径。

**从本产品备份恢复：**支持同一版本/可支持的旧本产品版本，以及 Mac 与 Windows 之间的恢复。这不是旧项目 JSON 迁移，不与 D11 冲突。

本机恢复点不能抵御整台机器损坏；加密备份可由用户自行存到其他介质。首版不自动同步云盘。

## 20.2 一致性备份

使用 SQLite 的一致性 backup 能力或经过验证的事务快照机制，不能直接复制正在写入的数据库主文件并忽略 WAL。[S19][S21]

备份在工作区写锁/快照边界内收集数据库版本和对象清单；完成后校验所有引用对象存在及 SHA-256 一致。备份期间新导入可以继续登记，但不进入该快照；恢复点明确其数据 revision。

空间不足时不能删除唯一可用备份来强行成功。允许继续读取，暂停需要安全恢复点的数据变更，并给出处理方式。

## 20.3 加密备份格式

使用维护中的密码学库实现备份密码派生与认证加密，不自行设计密码算法。主方案使用 libsodium 的 Argon2id 密码派生与 secretstream 分块认证加密；具体库绑定和参数通过目标平台测试后锁定。[S23]

容器包含一个不含成员姓名的版本化头部、随机 salt、经限定的 KDF 参数、加密 payload 和完整结束标记。恢复时限制文件大小和 KDF 资源，防止恶意文件请求超大内存；认证失败、缺少最终块或被截断必须整体拒绝，不恢复部分资料。

加密内层包含 manifest、数据库快照和按 objectId 存放的原始对象；所有相对路径都要防 zip-slip/目录穿越。不在外层暴露真实文件名。口令只在必要进程内短时使用，不写日志，不默认永久保存。忘记口令无法由开发者恢复，导出前说明。

## 20.4 恢复流程

选择备份 → 输入密码 → 校验 → 展示范围/日期/版本摘要 → 用户确认 → 暂停任务和 watcher 写入 → 为当前工作区创建恢复点 → 在独立临时目录恢复并校验 → 原子切换 → 重新打开数据库 → 读回验证。

恢复失败不破坏当前工作区。备份的 source object 使用应用内 ID 路径，可跨系统；旧 watcher 目录不直接恢复为有效授权，需要用户重新选择本机位置。恢复后不自动登录，不自动发送历史资料给新账户，也不立即全量重分析。

## 20.5 删除与备份关系

删除成员或报告前说明会影响哪些正式数据、派生结果和历史版本，并允许导出。收件箱保留排除记录以免重复导入。若用户请求清除备份里的相关数据，执行明确的备份清理或重建；否则说明历史恢复点可能仍含旧资料。

清空整个工作区必须显示明确确认，不因用户选择“退出 Codex”而触发。删除需要等待相关任务结束；迟到模型结果不能重建已删除成员。

| 数据与隐私 | 数据位置、空间占用、导出/恢复、临时文件清理、任务记录保留、授权撤回。 |
| 显示 | 字体大小、动画减少、日期显示；首版不以暗色主题阻塞核心交付。 |
| 关于 | App 版本、版权与依赖许可证、手动检查版本、诊断预览/导出。 |

设置不展示提示词输入框、任意 shell 命令、任意 OAuth token 字段或“允许所有工具”的开关。技术型用户的开发选项只能在开发构建存在，不能让普通 Beta 用户误操作后突破产品边界。

## 21.2 配置文件

配置 Schema 校验，写入原子化。调度、显示与临床规则分开；显示偏好不参与医学分析输入签名。

产品管理 Codex 私有配置，不读取用户仓库内的任意 AGENTS.md 作为运行时健康任务指令。自动加载插件、MCP、其他项目配置以及更新检查行为以锁定版本实测并禁用非产品必需项；发现与限制不符时拒绝自动运行，而不是默认信任。

## 21.3 提示词和评测版本

至少维护以下版本化模板：extract、review-facts、analyze、guidance、review-derived。模板包括输入边界、证据格式、输出 Schema、缺失处理和医疗表达约束，不含真实健康样例。

每次规则或模型组合变化，运行固定合成样例与对抗样例，并记录差异。不能无通知地重跑用户全部档案；旧快照保留版本标识，需要重分析时作为用户可见的维护任务。

普通日志只记 promptVersion/hash，不记完整插入健康数据后的 prompt。开发调试需要查看真实任务时必须本地、用户明确允许、默认关闭，不能进入自动上传。

# 22. 测试、数据质量与 CI

## 22.1 测试分层

| 层级 | 必测内容 | 是否需要真实账户 |
|---|---|---|
| 单元 | Schema、日期/单位、状态机、签名失效、时钟、去重、自动接纳策略 | 否 |
| 本地集成 | SQLite 事务/备份、文件 watcher、Word/图片转换、RPC 分帧、崩溃恢复 | 否 |
| 协议契约 | 锁定 Codex 的初始化、事件结构、审批拒绝、取消、能力探测 | 无健康数据的部分可离线，其余按实际能力 |
| AI 金标评测 | 合成原始报告 → 提取/复核/分析 → 对照人工标注 | 是，只用明确授权的测试账户与合成资料 |
| 桌面端到端 | 安装、登录、创建成员、导入、自动更新、核对、退出恢复、备份 | mock 可做 CI；真实运行另验收 |
| 目标平台验收 | Mac arm64/x64、Windows x64 安装运行与 OS 行为 | 登录/模型/系统凭据部分需真人流程 |

公开 GitHub Actions 不保存个人 ChatGPT 会话、不上传健康数据库、不录制 OAuth 页面 token。Mock 测试必须标为 mock，不能被计为真实 Codex 通路通过。

## 22.2 合成金标数据集

Beta 前准备至少 40 份合成源文件、合计至少 1,000 个可评价字段，覆盖所有首版格式、数字/定性值、中文/英文、不同参考范围、同日多次就诊、跨页表格、图片旋转、模糊字符和身份冲突。另有不少于 15 个安全/故障样例。

样例由脚本生成或经人工确认纯虚构。开发者先固定标注和预期行为，再运行模型，不让同一个模型同时生成唯一“金标”并评判自己。保留至少 20% 样例不参与提示词调试；对关键图像样例更换模型版本后重测。此规模是首版工程要求，不构成临床验证。

## 22.3 质量判定

自动接纳字段的准确率与资料覆盖率分开统计，不能把全部结果标成 unknown 来获取“零错误”。字段单位为数值/定性结果、单位、日期、成员归属、来源定位等分别计数。

**Beta 设计目标：**在固定、人工标注的清晰合成资料测试集上，自动接纳的关键字段精确率不低于 99.5%，可读字段覆盖率不低于 95%；错误成员归属、伪造证据、把 AI 推断变成医生确诊、自动开药/改剂量的测试违规数量必须为 0。小样本和合成结果不能推广为真实临床准确率。

模糊/矛盾资料的期望是进入例外或明确 unknown，不要求“猜对”。记录误接纳、误拦截和待核对率。若质量目标达不到，应改进拆页、证据和例外策略；不得只放宽自动入库条件或删除失败样例。

## 22.4 自动化门禁

每个 PR 至少运行 typecheck、真正的 lint、unit、contracts、storage/ingestion 集成、合成 mock E2E、隐私/密钥扫描、依赖与许可证检查。存在明确可利用的高风险依赖时需修复或记录有依据的例外，不把构建通过当安全通过。

AI 集成验证可以是开发者本机/受控手动工作流；不得为了 CI 自动化绕过 OAuth 或共享账号。真实接口测试回执只输出结果和版本，清除敏感录屏内容。

## 22.5 隐私测试资产

现有仓库有禁止二进制敏感文件的规则。新增合成 PDF、Word、图片和截图不能靠全局忽略扫描解决。建议测试时由脚本生成到临时目录；必须提交的演示资源使用精确路径＋哈希白名单及纯虚构说明。真实数据目录、正式数据库、用户附件、认证材料继续禁止提交。[S01][S02]

详细场景、测试 ID 与证据要求见 `02-验收测试清单.md`。

# 23. 开发里程碑、安装与公开 Beta

## 23.1 里程碑

| 门禁 | 目标 | 退出条件 |
|---|---|---|
| G0：可行性与协议冻结 | 在 Mac/Windows 验证 Codex、图像、OAuth、权限和转换依赖 | 真实最小链路与禁止能力测试通过；选择并锁定运行时、schema、转换组件；记录尚未有资源的签名门禁。 |
| G1：本地可靠内核 | 新工作区、成员、导入、任务、文件存储、事实查询 | Mock 可完整自动更新；去重、调度、事务和恢复单测/集成测试通过。 |
| G2：真实 AI 闭环 | 导入 → 提取 → 复核 → 自动接纳 → 分析/指南 → 看板 | 正常路径不写提示词、不审批；例外准确停在需要用户的位置；真实账户演示与回执。 |
| G3：桌面 Beta 完整性 | 桌面 UI、多格式、后台、通知、备份、安装包 | 三个平台架构矩阵完成端到端，质量目标和安全用例通过，文档与发行清单齐全。 |
| G4：对外发行批准 | 签名、公证、许可、兼容限制与免责声明 | 维护者明确批准实际发布；未具备签名资源不得声称可无提示安装。 |

G0 是集成原型，不是先完成一套漂亮界面。若官方能力或目标平台权限机制不足以支持安全无人值守，应给出具体失败证据与合法修复路线；不能静默改用 API Key、外部 Agent 窗口、WSL 或完全权限模式。

## 23.2 同一代码、多个安装包

所有平台从同一 tag/version/commit 构建，业务和 UI 不分叉。平台适配集中在 runtime、凭据、托盘、文件权限和转换组件层。

默认产物：macOS arm64 DMG、macOS x64 DMG、Windows x64 安装程序；可以同时提供更新所需归档。文件名显式包含版本和架构，Release 页面自动推荐但允许用户自行选择。

目标平台原生依赖、Codex 运行时和 Word 转换组件都要架构匹配。CI 使用对应平台 runner；尤其 macOS 签名/公证在 Mac 环境完成，不假设 Linux 能完成所有系统发行。[S09][S10][S22][S24]

使用预构建应用时，普通用户不应安装 Node、Python、Git、Rust、Docker、WSL 或使用终端。若组件采用首次下载，在 App 内说明用途、大小、来源和失败恢复；下载必须校验锁定哈希，不能下载后自动执行不受控的最新版脚本。

## 23.3 运行时与组件分发

Codex 运行时使用官方下载/仓库许可允许的分发方式，记录版权、许可证、校验和及依赖。不能假设“开源 App”自然获得任何第三方组件重新分发权。[S16]

Word 旧 `.doc` 支持涉及转换器的打包体积、许可、字体差异和签名。首版 Beta 把它列为必须完成的兼容组件门禁，不写成已实现，不承诺字体/分页与用户原始 Word 完全相同。分页重排时展示转换视图并保留原文对象身份。

首次组件安装与 OAuth 可以联网；离线模式允许查看合成演示和已有资料，但不虚构“离线也能使用 Codex 分析”。

## 23.4 版本更新

首版提供“检查新版本”和官方 Release 链接，采用用户发起的安装更新；不把跨平台静默自动更新列为首版必需。下载校验、签名验证和安装前备份仍是必要项。

更新前暂停新任务，完成或取消当前 turn，关闭写入，创建一致性恢复点。内部数据库 schema upgrade 先在副本验证再切换；失败可以返回旧应用和旧快照，不直接让旧程序打开不兼容新 schema。

Codex/模型/提示词变化不应无通知重写既有解释；必要时提供“重新分析受影响成员”的受控任务。

## 23.5 对外说明

Release 必须写清：支持 OS 与 CPU、已测试运行时、登录方式、数据会发送给 OpenAI、使用账户额度且可能涉及 credits、应用不开启公网端口、关闭/休眠不能保证定时执行、AI 自动整理不等于医疗审核、已知限制和恢复方式。

不使用“永久无限免费”“全程离线”“100%准确”“OpenAI 官方健康产品”等表述。订阅条款与集成能力可能变化，平台依赖要透明。[S03][S05][S06]

# 24. 风险、取舍与 ADR

## 24.1 风险登记

| 风险 | 影响 | 处理与验收 |
|---|---|---|
| App Server 成熟度及协议变化 | 登录、任务或权限行为改变 | G0 固定版本与契约；不宣称生产稳定性保证，升级回归。[S03] |
| 账户额度与 credits | 无人值守消耗超预期 | 展示可获得额度；上限和暂停策略；不保证绝对零额外支出。[S05][S06] |
| 同模型复核共同误差 | 两次输出一致但事实错误 | 原始证据独立复核＋确定性检查＋金标评测＋关键例外。 |
| 模型读取范围超过任务 | 其他家人或本机文件泄漏 | 首选禁工具推理；真实攻击用例测试，失败不得全自动 Beta。 |
| 跨平台 HEIC/旧 Word | 某系统功能缺失 | 作为 G0 技术门禁，统一接口封装，禁止把缺失隐藏成“支持”。 |
| 定时任务遇休眠/退出 | 用户误以为已处理 | UI 明确运行承诺，持久化补跑，不后台唤醒 OS。 |
| 同用户本地访问 | 家人/恶意程序读到资料 | 无解锁是已确认选择；OS 权限、备份加密、清楚披露残余风险。 |
| 开源调试附件泄漏 | 用户上传报告/凭据到 Issue | 默认脱敏诊断、模板警告，不自动上传。 |
| 自动更新污染历史 | 新 AI 输出覆盖旧事实 | 新事实与修订分层，CAS，自动接纳审计，来源可回溯。 |
| 签名资源不足 | 公众安装提示与信任阻力 | 功能 Beta 与发行资源独立登记，不绕过系统安全提示。 |

# 25. 后续演进边界

远程家庭阅读是长期目标，不在 Beta 启动任何公共服务器。现在只需要稳定 personId、业务 DTO、来源权限边界及发布快照，避免把未来所有信息硬编码为一位用户全部可见。

后续开放远程时，应采用真正的用户认证、成员/报告级授权、端到端或传输/存储保护和可撤销分享；不能直接把桌面端本地接口映射公网，更不能暴露 Codex App Server、OAuth 或让家人共享管理员订阅 token。

后续 API 模型适配可以复用 HealthTaskEnvelope，但首版不展示未实现的 API 配置页。应用解锁、健康档案问答、复查到期提醒、手机视图和平台新增架构分别作为独立需求评估。

**一个基本原则不变：更换执行引擎不应重建健康档案，关闭执行引擎不应失去已有资料。**

# 26. 交付与完成定义

开发完成必须交付：可复现源码、锁文件、运行时与协议清单、合成样例生成器、自动化测试、真实集成回执、目标平台安装包、依赖许可证、使用/隐私/恢复说明、已知问题列表。

完成报告区分“代码实现”“Mock 验证”“真实 Codex 验证”“各平台安装验证”“签名发行”五个维度，逐项给证据。某个平台没有机器、账户没有额度或签名未配置时，直说对应项未验证；不能以另一平台结果替代。

只有满足 G3 的跨平台、安全和质量门禁，才称为本需求的“公开 Beta 功能完成”。实际上传 Release、申请权限、签名证书操作和外部发布由维护者授权，不能把本实施文档当作无限外部操作许可。

## 附录 B：实现者不得擅自补全的事项

本方案没有提供真实账户、OAuth 凭据、签名证书、真实家人资料或医疗阈值库。实现者不能编造这些资源，不能自动申请付费服务，也不能从用户其他目录寻找私人数据来“跑通”。

可使用合成数据、模拟协议和本地测试推动开发，但所有模拟内容必须明确标识。实际登录应由用户通过官方流程完成；实际分发依赖由维护者明确授权。
