# 家庭用户内容验收

## 要达到的结果

家庭成员打开应用后，能知道已有检查说明什么、哪些变化值得留意、为什么，以及下一步能做什么。身体状况不能被模型处理状态取代。成员差异、检查条件、原报告安排和本人计划必须在整个处理与展示链路中保留。

本清单检验软件内容及交互，不代替临床专家评审。模型可调用、任务成功、测试通过都不能单独证明健康正文可用。

## 页面与状态

| 页面 | 用户要得到什么 | 必查状态 |
| --- | --- | --- |
| 家庭总览 | 区分家人，理解整体情况，找到自己的健康解读 | 多成员、多系统、无资料、旧解读、长说明可展开 |
| 健康总览 | 看懂主要健康问题和先后顺序 | 同一主题的多种解释、超过三项、紧急事项、资料不全 |
| 身体与指标 | 具体身体情况、指标含义和历次变化 | 临床条件、不同单位或口径、缺日期、文字检查、相关行动 |
| 检查时间线与详情 | 区分每次检查及报告内的不同检查日期 | 时间范围、历史对比、无日期、来源、可选的报告整理 |
| 日常生活 | 饮食、运动、睡眠、营养补充及作息的综合做法，随后查看医疗安排 | 五领域、儿童、长辈限制、本人偏好、通用/个性化依据、采纳、回顾日期 |
| 原始资料 | 按需核实原报告，并理解资料使用范围 | 有原件、移出分析、重新纳入、删除提示 |
| 报告收件箱 | 知道资料是否已导入、归属谁、如何处理 | 未归属、待处理、重复、失败、已转处理中心 |
| 处理中心 | 只在需要时知道进度、失败原因和恢复入口 | 等待、失败、局部未纳入、完成；不能当作健康风险 |
| 后续事项 | 知道谁要做什么、何时做、如何更新进度 | 多成员、安排时间、原医嘱时间、已完成及来源 |
| 设置 | 理解模型、授权、自动处理和本机资料管理 | 更换模型、未连接、默认不自动发送、备份、版本限制 |

健康正文中的日期、未散瞳、是否空腹、用药背景、资料过旧等是必要的判断条件，不能为了去掉“过程信息”而删掉。收件箱和处理中心的可操作进度属于管理信息，可以保留，但不混入身体结论。

## 完整流程检查

1. 逐份提取报告事实与临床条件；医生原安排保留否定、前提、期限和来源日期。
2. 成员综合一次读取授权范围内的全部资料和本人背景，不用分段摘要替代整体理解。
3. 同一健康问题的事实、趋势和参考解释使用同一主题键；不按器官或共同行动猜测合并。
4. 正文中的软件阶段、内部标识和编辑决定在发布前被发现并局部处理；健康解释与必要条件仍保留。
5. 总览按主题提供入口，完整解释与全部不同的行动仍可阅读；高影响事项不因首屏数量限制被截断。
6. 采纳建议不会覆盖本人已有计划；用户自己安排的时间与原医生建议的时间依据分开。
7. 阅读页面不调用模型；旧解读可辨认地保留，不冒充新流程结果。
8. 家庭和成员总览综合多个已检查系统，不复制第一条器官结论；保留整句解释、限制和未知背景，不按字数剪去条件。
9. 日常生活一次综合五个领域，不单独跑五次模型。普通日常起点与有个人依据的建议明确区分；缺依据时可以说明暂不新增保健品，不能凑购物清单或剂量。
10. “暂不新增”“先与医生讨论是否需要”和一般作息的“开始试行”不误判为开始服用；同段明确新增服用、剂量或真实医疗安排仍须相应证据与重点核查。

## 验证证据的层次

- 单元与组件测试：证明具体回归行为，不证明模型自然生成的正文质量。
- 纯虚构真实模型案例：分别覆盖儿童视力、长辈血压与肾功能、成人近期指标变化；固定输入并冻结最终发布内容、页面读模型和来源版本。
- 独立内容评审：逐项核实数值、日期、必要条件、个体背景、原安排、行动及补充问题；原始模型回合输出不能代替最终内容。
- 实际应用截图和操作：确认页面能读、能展开、能到达来源，按钮与文字含义一致。
- 本地安装验证：记录构建版本及资料是否被修改。安装新代码不等于历史报告已经重新处理。
