同一隔离 App userData 上，用未签名解包应用实际点击 V3 建议卡片的“加入后续事项”：点击前该建议只是提议，点击后出现 1 条已采纳行动；页面重载后仍为 1 条。完全退出应用并用相同隔离 userData 重启后，再次进入“生活与行动”，该卡片仍显示“已加入后续事项”，已采纳行动仍为 1 条，没有重复创建。自动化脚本 `scripts/capture-member-v2-personal-ui.mjs --adopt=true` 现同时支持新版 V3 建议和旧版提议，并对重载持久化及数量稳定性做失败即报错的检查。两次机器回执分别在隔离临时目录 `fhd-v3-adoption-smoke-first/audit.json`、`fhd-v3-adoption-smoke-restart/audit.json`，均使用虚构成员和虚构报告。

这证明了**当前合成快照下的主动采纳与跨进程保存**。另有一条数据库／服务层回归测试使用合成报告和模型替身：采纳行动并标记完成，新增本人补充触发新版 P02 快照发布后，旧行动仍保持完成状态且只有一条。它验证保存与关联逻辑，但**不是实际模型或打包 App 的资料刷新旅程**；后者以及旧真实工作区升级、已签名安装版同类旅程仍为 **NOT_RUN**，不能由本次重载检查推断已通过。

再补一条**同一合成工作区跨版本回归**：先在旧 `derived-v1` 路径保存派生快照、物化一条旧版建议并由用户采纳、完成；同库另有已接纳报告事实、本人补充、手工修正的报告元数据和用户自建事项。关闭重开后，用模型替身只运行一次 V3 P02，确认新成员快照发布，事实版本未变，旧快照正文未被改写，旧采纳及其完成进度、本人补充、报告修正和用户事项均保留；再次重启后新快照和进度仍可读，相同签名重试为 0 次调用。测试最初发现：新行动和旧已采纳行动有相同稳定键时，V3 页面仍可能再次提供“加入后续事项”，导致重复行动。现只有稳定键相同且身体系统范围有交集才复用旧行动；缺键或范围不匹配时不自动合并。回归证明同方向的旧完成事项在 V3 页面被识别，再次点击也不会生成第二条。此测试覆盖现有数据库结构中的旧内容共存与 V3 发布，**不等于**真实旧安装包升级、实际家庭数据库迁移或真实模型链路；这些仍为 **NOT_RUN**。
