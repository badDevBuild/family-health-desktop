# 家庭用户阅读体验优化方案

## 目标

打开看板时，普通家庭成员应依次回答四个问题：

1. 我目前的身体情况怎样？
2. 哪一至三件事最值得先看？
3. 报告发现了什么，这些变化该如何理解？
4. 接下来可以做什么，哪些情况需要与医生确认？

界面负责组织已经发布的内容，不重新生成医学判断，不把缺少检查变成“正常”，也不从一张趋势图推断病因。

## 阅读结构

```text
整体结论（一句话，来自已发布整体解读）
  ├─ 身体情况速览：值得留意 / 本次未提示问题 / 已有检查记录 / 尚无相关检查
  ├─ 优先关注：最多三个普通主题；及时处理的重要主题不折叠
  ├─ 和以前相比：保留已经发布的变化解释
  └─ 按身体查看
       ├─ 检查发现或历史变化：完整原句、必要数值和条件
       ├─ 这说明什么：解释与可能关联，不冒充确定病因
       ├─ 理解时别忽略：影响结论的限制始终靠近正文
       └─ 接下来怎么做：第一步 / 何时 / 何时回看
            └─ 原始依据、医学来源和其他说明可展开查看

日常生活
  ├─ 五类导航：饮食 / 运动 / 睡眠 / 营养补充 / 日常习惯
  ├─ 先从这些小事开始：不同主题的至多三个阅读入口
  ├─ 每类完整建议：为什么 / 怎么做 / 何时 / 注意事项
  ├─ 复查与就医：与日常习惯建议分开
  └─ 我的计划：只有本人明确采纳后才改变
```

## 已实施的展示层调整

- `ReadingHealthMap`：与身体目录、系统卡片共用 `systemReadingStatus`。根据已经发布的身体系统状态分组，不计算健康分数。有相关事实、但完整系统判断尚未发布的部分归入中性“已有检查记录”，不能写成没有检查，也不据此推断正常或异常；无相关事实的系统显示“尚无相关检查”，不能进入“本次未提示问题”。同时用文字、分区和颜色表达，颜色不是唯一信号。
- `MemberProfileV2`：保留整体健康结论；将报告发现、变化、参考解释、理解依据与必要条件分层呈现。长段落限制行宽，正文不小于 16px。完整整体情况、个人资料依据、医学来源保留原有展开入口。
- 派生正文中的完整安全 HTTPS 引用显示为来源标签，不直接露出 Markdown 语法，也不新增链接执行入口。报告原文、来源摘录、原句绑定的医生指示和本人计划保持原样；非综合的行动入口按真实来源分流，不按标题猜测。
- 整体结论因部分内容未发布而需要重新组织时，标题仅作为短导航，说明现有主题数及其主身体系统数；主题原文、否定词和适用条件保留在完整说明及优先关注中，不把多个长主题再次拼成大标题。合格的整体结论标题保持原样。
- 长整体说明收起时，家庭卡片和成员总览仍直接显示已发布的具体重点。全部高影响主题与至多三个普通主题按原有顺序展示，不用计数替代身体情况。每项的完整解释、阅读依据、主身体系统及总体适用条件保存在同一个展开单元中，默认先呈现主题，不让长文挤走其他重点；旧投影缺少这些上下文时只显示完整主题入口。完整长述仍可展开，点击导航入口不调用模型。
- `ReadingMetricPreview`：在指标入口提供轻量 SVG 小图，横轴按真实日期间隔绘制；仅显示同一个严格可比序列中的精确值。不同检测分组不拼线；缺失、界限值、不可比值、同日多条结果会中断连线。屏幕阅读器同时获得日期、原数值、单位和记录数量。
- `DailyLifeGuide`：五类建议可直接定位正文；保留不同主题的三个起步入口，完整建议不删减。已有计划和采纳操作的安全门禁不变。
- 样式沿用温暖绿色、暖灰和琥珀色；交互目标至少 44px；窄屏为单列，导航不依赖横向滚动；不新增外网依赖。

## 不做的事情

- 不把“数值下降”自动变成“改善”，也不把上升自动变成恶化。
- 不把不同机构的参考范围当作统一标准线。
- 不从报告数量、系统数量生成健康总分。
- 不用通用文字填充缺少的个性化结论；通用生活建议仍明确标记。
- 不截掉否定词、左右侧、检测条件、时限和重要风险。
- 不自动采纳建议，不改写本人计划，不因点击页面调用模型。

## 验收

1. 首屏是整体结论，不是处理或核对状态；全部重要主题仍可访问。
2. 同一解释中，检查事实、理解依据与限制不混成一整段。
3. 小图与文字表达相同日期和数值，无法比较时不画伪趋势。
4. 五类日常建议可一键定位，缺少建议如实说明；不会自动采纳。
5. 打开原始依据、完整说明、不同检测分组的历史表格仍正常工作。
6. 测试使用合成资料；真实报告、姓名、正文和截图不写入公开仓库。
7. 安装后需在真实窗口核对桌面与窄屏：字距与行宽、溢出、滚动、展开、导航焦点，以及新综合结果是否已显示。

## 可复用组件

`ReadingHealthMap({ systems, onSelectSystem?, compact? })`

- `systems`：`BodySystemSummaryV2[]`，必须来自现有读取接口。
- `onSelectSystem`：只导航至系统详情，不发送资料。
- `compact`：家庭总览等较小空间的紧凑呈现。
- 省略回调时为纯静态速览。

`ReadingMetricPreview({ series })`

- `series`：同一指标入口已有的 `MetricSeriesSummary[]`。
- 多个严格分组时不绘图；详细历史仍由现有分组图和表格承担。
- 图表使用中性含义，不能替代报告原文和综合解释。
