# 上传后自动整理

本页描述普通上传的产品契约。它不授权清空、覆盖人工记录、变更成员归属或采纳个人计划。

## 用户看到的流程

选择成员 → 上传资料 → 查看处理进度 → 阅读更新后的健康看板。

上传区域固定说明：为整理报告和生成所选成员的健康解读，原件及必要的成员历史事实、解释条件和本人补充将发送给 OpenAI/Codex。选择文件或拖入资料就是启动这次处理，不再追加“立即处理”“批准”“二次复核”弹窗。

正常浏览、页面刷新、切换成员以及重复收到进度快照都不触发模型调用。取消文件选择不会创建任务。重复文件不自动重读已完成资料；重复上传也不借机处理其他旧的待核对文件。

上传时明确选择的成员就是本次资料的归属。报告上的姓名不同、缺失、脱敏或被遮挡，只记录为非阻断说明，不要求再次确认身份，也不生成别名或改写报告姓名。成员档案的“上传报告”入口直接绑定当前显示成员；“手动补充”独立用于症状、用药、自测及生活情况。收件箱和文件选择窗口都明确展示本次上传对象；仅保存原件时不发送给 AI。

同一原件明确上传给不同成员时，各自保留独立文档，不覆盖另一位成员已有结果。同一成员重复上传仍去重。目录自动扫描和未明确选择成员的资料不视为用户完成归属，保留相应范围与身份保护。

旧版本中仅因姓名不符或姓名不可读而未纳入的资料，可在明确选择的报告范围内使用正常重核入口继续。排队事务核实既有的用户归属后，将旧姓名阻断标记为已被归属政策替代并保留审计，再由模型读取原件；这不代表确认两个姓名相同，也不生成别名。升级或重复上传本身不会自动重跑旧资料，其他医疗来源问题和人工保护继续有效。

## 后台工作

1. 复制前保存本次精确上传意图，包括所选成员、文件项、账号和授权版本。原件进入本机保险库后，文档与意图在同一事务中绑定并记录哈希。
2. 自动创建持久任务。尚未连接时显示等待连接；连接后沿同一资料范围继续，不重新要求一次业务确认，也不把旧账号授权转给新账号。
3. 模型整份读取原件。本地只做格式、来源、范围和结构检查，不用 OCR 或脚本代替模型识别医学内容，不切分原件语义。
4. 返回格式损坏时，允许同一任务一次持久化的完整原件格式恢复；内容来源问题仍走既有的有限目标修复。重启、断点续跑不能重置额度。
5. 能可靠确定的结果正常保存。明确选择成员时不因姓名差异隔离结果；人工保护冲突或仍无法确定的医疗内容保留说明，不自动改归属、不猜数值，也不因一份资料不完整而阻断其他报告。
6. 同一成员连续上传的任务按队列处理；已有后续上传待整理时，前一批不抢先生成不完整的最终综合。最终综合读取该成员当时有效且允许使用的全部事实、必要条件和本人补充，不借此授权其他成员或被排除的资料。
7. 自动完成综合、必要局部修复和重点复核，发布整体健康总览、身体系统解读及五类日常建议。内部模型复核不是要求用户批准。

确定结果与附属字段分别接纳：结果有独立且完整的原件依据时，未核实的检查日期、报告日期、机构或标题只保留对应说明，不把整条结果一并丢弃。原始回包和未核实字段仍留在正式审计中；未知日期不参加时间趋势。决定项目身份的标题、左右侧、检测条件、单位或比较符号不属于可忽略的辅助信息，旧记录里已确认的内容也不能借此被置空。

日期按适用范围绑定：模型可把有依据的封面或章节日期引用到同次检查的后页结果；历史对照图按各数据点的时间列分别绑定，不套用报告主日期。日期字段被隔离，或模型已经读取相关日期却漏绑到结果时，进入既有一次有界补核。补核仍无法确定时保留正确结果和日期说明，不重新开启修复预算。相同多日期摘录的 ID 不能代替具体时间列的引用，日期也不能只写在展示名里。

指标详情区分单项检查日期与所属报告时间。单项日期为空时，可以只读显示本原件已核实的检查、采样、就诊或签发日期，并明确标注它属于报告；不改写单项日期，不把它加入趋势横轴或当作最新检查。无可靠报告时间时仍保留说明。升级只改善现有来源的显示，不自动重读旧报告，也不从文件名、项目名称或上传时间猜日期。

旧报告已有检查时期、数值或定性结果仍缺单项日期时，即使历史核查事项已关闭，也可在处理中心的可选维护入口显式选择重新核对。此提示不是新的错误或必办事项，不改变已完成状态，不自动加入上传队列。原件、旧值、条件与修订继续保留；只有原件来源唯一对应的日期补充才沿既有接纳流程保存，历史各列不能套用报告日期。排队事务再次检查成员、人工保护、活跃任务和精确授权范围。补充健康信息会使该成员整份综合失效；后续综合使用该成员全量事实与当前补充信息，统一重建整体解读和五类建议，不只刷新一段文字。

执行层以持久化的显式重核范围为准，不因报告已完成或没有旧警告而跳过模型读取。无旧事项时由当前任务、尝试、账号和授权绑定增量接纳，不制造医学警告换取写入权限；实际发现的未解决项目才在保存事务中新增说明。已完成收据必须有本任务的读取凭据，旧版错误跳过的收据在提取阶段续跑时重新核实；真正完成的报告和综合阶段续跑不重复提取。可选来源字段缺失按结构比较，不能因对空值计算哈希而使整个报告失败，也不能据此放过真实字段差异。

P04 允许精确等义的数值排版规范，以及在冻结的同一事实和同一来源位置内凭证据补绑引用；不允许近似舍入、换算或补造依据。单个目标缺少复核回执时，隔离该目标及实际依赖它的内容，其他已得到有效复核的独立内容可发布；错误范围、重复或未知目标仍拒绝。综合未发布的固定原因码会留存，不因清理模型正文缓存而失去排查依据。

“尚未提供治疗经过、检测前用药”等完整缺资料陈述不是用药操作；其中若包含独立的开始、停用、调整剂量或频次指令，仍按原操作边界处理。纠正资料缺口时使用本次已提供来源中的原称，不能自行换写方法编号、添加测量值，或顺带删除仍未知的治疗与用药背景。

日常建议因一条主张失效而改写时，可以去掉失效的身体系统标签，但不能增加新系统或变成空标签；剩余主张、依据和正文仍需通过独立性校验与完整复核。仅删除引用或标签不能当作已修复。

综合最后一次依赖检查仍采用局部隔离：若旧摘要残留已隔离结论的文字，旧摘要整体留在核查记录中，再从仍有效的结论及其原有不确定性重建；不改写报告事实，也不把原临床条件删除后继续沿用旧摘要。范围、身份或重复 ID 等整份错误仍拒绝发布。核查原因过多时明确记录省略数量与完整原因集合哈希，不能因审计字段超长把可靠结果一并丢掉。

上传或本机准备中断时，启动恢复只处理该意图已绑定的保险库原件，不重新打开任意旧路径，不夹带其他历史待处理文件。未复制的项终止并保留固定原因；已完成的重复资料继续去重。归属、原件哈希、排除状态、账号或授权版本变化时不沿用失效范围。同成员尚有有效上传项未落定时，不抢先发布只覆盖部分资料的综合。

重复核对时，来源引用边界变化不直接构成新结果。同一原件的单字段若从“整行引用”变为“标题与结果分别引用”，只有真实来源位置可唯一对齐、原始医疗字段逐字相同且没有人工保护或竞争记录，才判定重复。读取历史重复记录也只选已有的可追溯版本供看板和综合使用，物理记录及旧修订继续保留。不同侧别、日期、栏目、条件或医疗值仍独立对账。

来源竞争范围按实际结果或原医生安排所在页计算，不把仅承载报告日期、标题或背景的页当作结果页；这些引用仍保留并各自校验。旧局部原句与新行列槽位可以由同一原件真实共同全文唯一定位，并以不相交的结果位置证明不同字段。只凭名称不同、值不同、摘录编号不同或拼接文本均不能分离；重复位置、真正同格冲突和旧原句覆盖新结果仍保留核查。

每次保存都对读取条目逐一记账：已保存或可靠对应已有结果、原件明确未提供结果、暂未纳入，三者数量必须等于本次候选总数。漏掉去向的候选不能无声消失。模型已返回的清晰结果摘录若没有对应候选，进入一次有界补核，仍未补回则留下缺口说明。共同全文包含某段内容并不自动证明该段已被提取；只有实际结果引用落在其中才能视为承载。此检查不等于机器可以保证模型发现了原件上的全部内容。

界面将最近一次对账和历史读取版本分开。历史候选缺少可靠对应关系时保留审计，不能把历次版本相加叫作“本次遗漏项目数”，也不能因同报告有正式结果就声称所有未采用版本都已有对应结果。旧记录没有逐次对账时明确显示“独立未纳入项目数尚未确认”，不伪造确定数字。

实际连接中断后的恢复与模型正常思考区分：只有运行时明确报告可重试的连接失败才进入连接恢复预算。一次连续恢复最多五分钟或八次断线通知，非空模型正文恢复后才重置这一段预算；空事件、用量或重复断线不重置。超限只结束对应模型轮次并保留失败范围，其他任务和已完成结果不受影响，不因一般长时间推理误报断线。

## 问题只提示，不变成业务待办

| 情况 | 应用行为 |
| --- | --- |
| 单个字段或页面仍读不清 | 继续其他内容；在结果范围说明中列出缺口和原件入口，不冒充正常 |
| 原件空白、没有文字结论 | 保留空白或“未提供文字结论”的说明，不要求用户补出结论 |
| 用户明确选择成员，但姓名不同、脱敏或无法读取 | 按用户选择归属，保留来源原貌并记录非阻断说明，不再要求确认 |
| 目录自动归属与明确身份冲突、或与本人保护记录冲突 | 保留相应保护、原件与旧版本，继续其他资料 |
| 模型暂时繁忙 | 显示正在自动恢复，并沿既有限额与断点重试，不从头提取已完成报告 |
| 尚未连接、登录或额度不可用 | 保留本机队列和已有结果，显示真实等待原因；不能假装已完成或替用户完成登录 |
| 持续服务故障、文件超容量、转换能力缺失、本机空间不足 | 显示未完成范围和原因；不无限重试、不截断原件、不删除已有结果 |

“已完成，部分内容未能纳入”与“正在等待用户核对”是不同状态。正常内容缺口应采用前者；实际登录、额度、撤权、取消等执行边界继续有效。系统不能为了减少提示而声称已处理成功或接纳没有依据的内容。

已经结束但有内容缺口的任务归入“最近记录”，不再列入当前待办、不亮处理通知点，也不显示普通“重试”按钮。用户仍可自愿查看处理详情、未纳入范围和原始依据。

收件箱和成员档案的原始资料页使用同一份状态解释，不能在一处显示“部分内容未纳入”，另一处又要求“核对”。任务生命周期与综合结果也分开：有正式发布回执时显示“健康看板已更新”；综合未发布或没有可用结果时如实说明，不从“全部报告已读完”推断健康解读已发布。登录、额度、发送范围问题必须显示真实暂停原因，不能伪装成已整理完成。

## 不变的边界

- 原件、已完成事实、个人补充和个人计划不因普通上传被清空。
- 执行前、模型发送前后及正式保存时都重新检查范围和撤权状态。
- 同一账号的连接恢复可继续原任务，账号更换不自动继承敏感资料范围。
- 事实阶段搜索关闭；综合搜索沿用用户设置与风险说明。
- 正式更正已接纳结果、破坏性清理及权限扩展仍采用各自的显式操作，不藏在普通上传里。
- 界面显示的是实际可用结果和真实缺口，不保证不清晰或缺失的原件也能生成完整医学事实。
