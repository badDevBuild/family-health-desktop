# 成员档案 v2 实施基线

更新时间：2026-09-21

本文件记录 `family-health-member-redesign-v2` 的实施基线、数据保护边界与当前真实进度。状态只按代码、测试和实际运行证据填写，不以静态界面或设计稿代替验收。

## 1. 数据保护与回滚

- 原始资料仍通过内容寻址对象库保存；成员档案 v2 只增加语义索引和可重建投影，不改写原文件。
- 数据库 Schema 从 v28 事务升级到 v33。v29 建立成员档案语义索引，v30 增加可撤销的概念映射修正审计，v31 增加健康事件关系审计，v32 持久化结构化生活提议，v33 把用户自选目标、起始步骤、计划时间、负责人和备注与 AI 建议分开保存。升级前继续沿用现有一致性备份；迁移失败必须整体回滚。
- 删除报告时，事实、概念映射、身体系统关联、报告记录、健康事件、依赖索引和成员派生快照在同一事务中清理；原始对象按既有恢复点规则决定是否物理删除。
- 旧的 8 类器官字段保留兼容读取，新界面使用 12 个身体系统注册表。兼容映射是展示迁移，不重写历史派生内容。
- 页面读取使用只读 IPC。进入成员页、切换身体系统和打开指标历史不会创建模型任务。

## 2. 纯合成纵向夹具

夹具位于 `packages/test-fixtures/src/member-v2.ts`，不包含真实个人健康资料：

1. 心血管多年记录：验证三点趋势、正常与异常维度并存、真实时间轴和多来源依据。
2. 甲状腺语义：验证 TSH 别名归一，同时严格区分 FT4 与总 T4、FT3 与总 T3。
3. 一次检查多文件与历史列：验证事件与附件分离、历史日期不被错误套用为本次检查日期。
4. 混合冲突长报告：用于保留既有整篇读取、独立复核、字段冲突和局部修正门禁。
